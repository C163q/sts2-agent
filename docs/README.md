# 项目文档入口与专项约定

本文面向项目开发者，说明 sts2_agent 的文档分工与游戏资料取证要求。编写与维护文档时，同时遵循[文档规范](documentation.md)。

## 文档入口与职责

| 位置 | 职责 |
| --- | --- |
| [项目 README](../README.md) | 面向用户说明项目定位、当前能力、使用入口和必要前提 |
| [开发流程与协作约定](../AGENTS.md) | 开发阅读入口、实施与交付要求，详细操作通过链接引用 |
| [文档规范](documentation.md) | 可跨项目复用的文档编写与维护规则 |

| [开发与接口文档](development/README.md) | 持续维护构建、配置、Mod 加载、工具协议、错误语义及开发验证流程 |

当前 Mod、MCP、游戏及依赖兼容基线统一维护在[项目 README](../README.md#当前版本与前提)；专题文档链接该基线，带日期的证据保留其核对版本。

核对组件版本时，查看[Mod 清单](../src/Sts2Agent/Sts2Agent.json)与[MCP 服务入口](../src/sts2_mcp/mcp_server.py)。游戏基线的证据见[v0.111.0 迁移核验](research/2026-11-10-v0.111-migration-investigation.md)，底层观察结构版本见[观察格式说明](development/observation.md)。

## 游戏与上游资料

- 涉及游戏 API、Mod 加载、Godot 或社区库兼容性的结论，记录核对日期、游戏版本与分支、相关依赖版本或提交，以及可定位的证据。
- 本地证据标明相对于游戏安装目录的文件路径及必要的类型或成员名；上游证据链接作者维护的文档或源码，依赖具体实现时尽量固定到版本或提交。
- 说明接口所属层次及适用范围：游戏加载入口与内部接口、Godot API、社区库扩展、本项目对外工具接口；稳定性承诺须有上游依据。
- 本机安装位置作为示例，实际路径通过配置提供。游戏程序集、资源、反编译产物、个人存档和密钥留在仓库外，文档引用必要的路径与标识。
- 游戏或依赖更新时，重新核对受影响结论。阶段性调研保留原始基线，新的当前结论写入持续维护文档或新的调研记录。
