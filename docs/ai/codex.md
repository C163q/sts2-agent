# Codex 环境约定

本文仅适用于 Codex 环境。使用子代理时，另读 [Codex 子代理模型选择](codex-subagent-model-selection.md)。

## 沙箱权限与命令拆分

本项目按 Codex 默认沙箱下 `.git` 和工作区外目录只读、`/tmp` 可写的限制安排操作；具体权限以当前会话提供的沙箱配置为准。

会被沙箱拦截的命令必须独立执行，每次命令调用只做一件事：

- 写入 `.git` 的操作（如 `git add`、`git commit`）须分别调用，不能与 `git status` 等只读命令合并。
- 即使两个命令都会被拦截，也必须分开调用，例如 `git add` 和 `git commit` 不能合并。
- 不得通过 `&&`、`;`、管道、换行或脚本包装，将受限命令与其他操作放进同一次命令调用。
- 已有权限批准时，仍按上述要求拆分，便于单独授权、重试和确认结果。
- 全部操作均不受沙箱限制时，可以按需合并执行，例如 `cat README.md && rg -n 'Codex' AGENTS.md`。

以下是命令组织方式示例，提交说明和文件列表按实际任务填写。

不符合要求：

```sh
git commit -m "更新项目文档" && git status --short
```

```sh
git add AGENTS.md && git commit -m "更新协作约定"
```

符合要求：下列每个代码块分别作为一次命令调用，依次执行，检查前一步结果后再继续。

```sh
git add AGENTS.md
```

```sh
git commit -m "更新协作约定"
```

```sh
git status --short
```

命令因沙箱权限失败时，保持该命令独立，按当前环境提供的审批机制申请所需权限后重试；不要将额外操作加入重试命令，也不要通过包装命令绕过权限限制。
