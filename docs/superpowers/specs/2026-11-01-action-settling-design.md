# 动作完成后的生物画面稳定

## 目标与边界

修复击杀一名敌人后返回 `player_ready/complete=true`，原生退场使下一次合法动作得到 `stale_state` 的问题，并检查共用动作等待中的同类缺口。不改工具、参数、观察字段、状态令牌算法和 MCP 版本；易用性及 summary 预设不在范围内。

基线为 `f96364e`，游戏 v0.107.1（59260271）、RitsuLib 0.6.10。真实记录及原始响应核验见 `.tmp/2026-11-01-evaluation-report.md`。

## 设计

继续使用原生动作、状态校验和 250 毫秒观察稳定窗口。在共用 `ActionObservation` 中补充生物画面的有限生命周期：尚未完成的死亡任务、正在移除的节点，以及会延后改变生命条、意图或可见性的有限 UI 过渡。针对原生未保存引用的 UI 渐变，仅跟踪实际创建的 Tween；不等待循环骨骼动画，不以 `IsPlayingDeathAnimation` 的非空标志代替任务完成状态。

这些检查读取原生生命周期，不改游戏逻辑、不阻塞游戏线程。仍通过每帧异步采样等待，保留 25 秒截止时间及 `timeout/complete=false`。待输入选择和未知界面沿用原有停止边界，不能等待可能依赖用户选择的父任务。

三选一的选择边界须先经过原生禁点时间与候选入场动画。复用奖励选牌已有的 `CanSelect` 和有限卡牌/按钮 Tween 检查，不等待被选牌暂停的父动作；其他选择类型和人工输入边界保持原有优先级。

不采用固定加长等待：不同敌人的死亡时长和复活机制不同。也不放宽令牌或自动刷新并重发动作：真实外部状态变化仍应被拒绝。

## 验证与交付

在独立游戏实例中先证明未修复版本存在击杀退场时的令牌变化，再验证修复后结果在退场完成后返回并可连续行动。回归覆盖卡牌和药水击杀、非致死出牌、结束回合触发死亡、复活与转阶段、选牌和最终胜利；同时检查奖励、资源、地图和结算已有等待是否覆盖相似延迟。

运行完整 Python 测试、C# 边界检查和真实图形场景。交付 Mod 0.32.0；MCP 保持 0.27.0、schema 保持 16。验证后提交并备份安装，正式游戏需完整重启才加载新 DLL；保留当前对局和 Workshop 管理的 RitsuLib。
