# 通用事件第一阶段规格

## 范围

实现已确认的[事件调研第一步](../../research/2026-10-31-events.md)：默认与战斗背景事件的可见观察、选项详情、原生选择、完成后的前进，以及选牌、奖励、战斗往返和非战斗死亡边界。假商人继续使用商店接口。占卜小游戏、Trial 的确认弹窗和未知专属界面明确停在 `manual_input_required`；不自动操作。保持单人范围，不新增地图选路。

## 接口

新增 `inspect_event()` 与 `choose_event_option({option_id: int32 >= 0})`。后者只接受这一个字段，使用当前观察令牌；可连续使用动作返回的新观察。完成事件的原生前进复用 `proceed()`。

基础观察新增 `scene: "event"` 和 `event`：`status` 为 `visible` 或 `covered`，其余字段为 `name`、`description`、`options`、`proceed`。覆盖时其余全部为 null。每个选项有 `id`、`title`、`description`、`enabled`、`lethal_warning`；详情额外提供 `hover_tips`。只读取当前显示的正文与真实按钮；文字展示动画尚未完成时不提前披露完整正文。ID 绑定事件实例及选项身份，换页不能误点旧 ID。

`lethal_warning` 表示原生红框警告，不额外推算复活或禁用危险选项。只有事件完成后生成的原生 PROCEED 按钮属于 `proceed`；普通选项即使 `IsProceed` 为真也由选择工具执行。

## 执行与结算

通过真实 `NEventOptionButton.ForceClick()` 进入 EventSynchronizer。跟踪真实选择任务、事件初始化及 Resume 返回任务；不能仅等待选项任务列表。先识别可操作子界面，再判断父任务完成；父任务等待选牌或奖励时允许返回下一次输入。

战斗开始前监听并复用战斗日志与完成判定；允许首回合自动机制、选牌及直接胜负。奖励后的原生前进可恢复父事件，必须等待 Resume 效果、卡牌预览、资源动画完成。非战斗死亡返回 `run_lost`；未知覆盖页返回 `manual_input_required`。未稳定的页面不得提前报告完成。

事件文本输出英文，保持游戏语言、缓存、RNG、页面及选项不变。对目标版本缓存的本地化引用使用分离的英文格式化数据；不得调用生成选项或随机属性补全文本。占卜与确认弹窗在观察中分别标识 `screen.view: "divination"/"confirmation"`，并提示需要人工输入，不提供操作权限。
