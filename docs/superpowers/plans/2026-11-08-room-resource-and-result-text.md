# 房间资源与结算文字修复计划

> 当前状态：已完成，2/2；独立审阅的一项重要问题已单轮修复并验证，已合入 main 并清理临时分支。人工历史页的复用清理限制保留在实施记录，功能验收使用独立进程。

> 执行方式：使用 executing-plans，在当前工作区的临时分支顺序实施，结束后一次独立审阅；用户已批准修复范围及自行合入 main。

**目标：** 补齐已知房间切换期间最终公开的资源变化，并让结算 texts 保留未被结构字段表达的正文。

**依据：** [反馈复核](../../research/2026-11-08-early-playtest-feedback-review.md)与[开发核验](../../research/2026-11-08-early-playtest-feedback-development-notes.md)。

**结构：** 资源可见性由 RunResourceJournal 管理，纯记录状态从游戏 API 中分离；复用既有动作缓冲和房间／地图生命周期。结算由同一个原生读取器识别已结构化控件并排除其文字，Python 预设继续共用结果。

## 共用约束

- 英文代码注释、中文文档、英文 Conventional Commits。
- 仅发布已有公开基线及最终实际显示的资源端点，普通隐藏／覆盖不补记；战斗内生命去重。
- 保留实际已公开的中间变化顺序；同一遮挡区间没有公开的中间数值不得逐项泄漏，按该区间可确认的端点表达。
- texts 按控件来源去重，保留同字正文、未结构化进度、完整故事和可滚动正文。
- 工具参数、可用性、终局等待策略和 TODO 不扩展；测试入口维持原有双重门控。
- 核对目标程序集后调用游戏／Godot API，操作仍在游戏线程进行。

## 审阅重点

- 跨房间未曾显示的中间数值、隐藏标签和错误／取消流程不会在恢复后泄漏。
- 入场治疗不与战斗日志重复，金币动画的逐帧数值不会成为额外事件。
- 多次公开资源变化及其他事件顺序正确，缓冲上限仍有效。
- 结算去重不误删与按钮／分数文字相同的独立正文。
- outcome、summary、epoch、unlock、history 的正文及展示中状态均保留。
