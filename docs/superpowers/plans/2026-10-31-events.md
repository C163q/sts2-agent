# 通用事件第一阶段实施计划

当前状态：实施中。共 4 项，已完成 3 项；实现和全部验证已完成，正在创建提交与安装，剩余最终交付记录。暂无阻塞。

> 执行方式：使用 executing-plans 在当前会话逐项实施；测试遵循 test-driven-development。已有自主完成授权，无需重复确认方案。

**目标：**让 LLM 通过当前可见事件选项完成第一阶段事件交互。

**架构：**独立 EventInspection 负责可见读取与身份映射，EventTaskTracker 跟踪原生异步生命周期，GameAdapter.Event 执行真实按钮并接入共享结算边界。Python 层严格投影、校验和维护观察权限。

**技术栈：**C# net9.0、Godot、Harmony、RitsuLib 0.6.10、Python MCP 1.26.0。

**规格：**[第一阶段规格](../specs/2026-10-31-events-design.md)；目标 API 与缓存引用依据[源码调研](../../research/2026-10-31-events.md)。

## 全局约束

- 游戏 v0.107.1，提交 59260271；不得猜测 API 或直接改状态执行动作。
- 单人、中文文档、英文注释与工具文本；遵循可见信息边界。
- 占卜与确认弹窗只识别人工边界；地图不新增选路。
- 真实游戏验证使用隔离用户目录，不操作正式对局。

## 审阅重点

- 换页旧 ID、锁定选项、布尔/超大整数参数不能误点。
- Covered、文字渐显、占卜遮罩不能暴露隐藏信息。
- 父任务等待子选择时可继续，Resume 尚未完成时不可提前操作。
- IsProceed 普通选项不能被错误替换成地图前进。
- 非战斗死亡、首回合自动结算及动态英文缓存保持完整边界。
