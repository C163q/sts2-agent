# 游戏观察的信息边界

本文记录基础游戏观察的已确认要求。目标是将当前静态画面中的可见游戏信息表达为 LLM 可接受的文本；当前实现与限制见 [战斗观察 JSON](development/observation.md)。当前样本对照见 [战斗画面核对记录](research/2026-10-29-battle-observation-audit.md)，字段来源见 [获取方式调研](research/2026-10-29-observation-data-sources.md)。

## 基础观察

- 以采样时的当前画面为准，覆盖可见玩法文字、数字、对象外观、图标、计数、牌序、按钮及显示状态。版本、Mod 调试覆盖层及传输控制信息不交给 LLM；默认费用文字颜色也不重复输出。
- 被遮挡、未展开、未悬停的信息不自动补齐。半隐藏手牌可记录可见名称、费用、位置与外框。已识别卡牌允许直接提供固有牌型、稀有度和实际外观卡池，不要求小标签展开；不能直接附送完整效果、关键词和目标规则。
- 手牌效果通过专门调用一次查看全部当前可见手牌，沿用稳定卡牌 ID；文件接口与 MCP 工具的格式见 [手牌详情 JSON](development/hand-inspection.md)。牌面正文及悬停解释的已核实来源见 [手牌查看来源调研](research/2026-10-29-hand-inspection-sources.md)。
- 界面入口和资源图标的悬停说明通过专门的文件调用和 MCP 工具提供，格式见 [界面说明 JSON](development/ui-inspection.md)，覆盖范围及来源见 [界面悬停说明核查](research/2026-10-29-ui-hover-tip-audit.md)。双方 powers 和敌人当前意图解释合并通过 [战斗对象详情调用](development/combatant-inspection.md) 提供，支持文件接口与 MCP；遗物通过专门的 [遗物详情调用](development/relic-inspection.md) 查看当前可见条目的正文、屏幕计数和共享解释，支持文件接口与 MCP。基础观察不自动附送这些说明。
- 药水正文及额外解释通过专门的 [药水详情文件调用](development/potion-inspection.md) 提供，不使用药水或读取未来生成结果。通用“药水栏位”帮助每次固定提供一份，即使当前没有空槽；空槽不再重复说明。
- 基础观察不自动查看其他界面，也不读取未展示的牌堆内容、抽牌顺序、未来随机结果、敌人后续动作或内部状态机。
- 专门的 [牌组查看调用](development/deck-inspection.md) 真实打开原生牌组页，一次返回整个可浏览牌组，包括滚动区外卡牌，不自动逐屏滚动。支持文件接口与 MCP，默认摘要，可选完整正文、升级预览与排序；页面保留到显式 `close_card_view` 或人手动返回。此调用不改变基础观察的静态画面边界，也不授权读取抽牌顺序；设计和 API 核对见 [牌组查看设计](research/2026-10-29-deck-view-design.md)。
- 专门的 [战斗牌堆查看](development/pile-inspection.md) 真实点击抽牌堆、弃牌堆或消耗牌堆入口，返回整个原生浏览列表，支持摘要及完整正文。抽牌堆只按原生显示序返回，不能返回真实抽取顺序；空抽牌/弃牌堆保留原生气泡反馈，入口未显示时不强行点击或读取隐藏内容。
- 专门的 [地图查看](development/map-inspection.md) 真实打开当前幕地图，返回全部可滚动浏览的节点和绘制连线，包含当前点与已走路线。当前可选节点遵循原生界面及飞鞋等规则，与连线分开；不读取未来幕或提前揭晓问号，也不授权选路动作。地图通过独立 `close_map` 关闭。
- “看不见”与数值 0、空集合不同。只有已核对的 UI 规则能够确定含义时，才允许做无信息增益的归一化，例如正常显示且无遮挡的生命条没有格挡标记时记为无格挡。
- 图标不能被静默丢弃，也不能借内部对象信息附送未显示的完整说明。可以保留当前图像或对应图标的可见语义；无法仅从当前画面确定的含义应保留未知。
- 允许将外观可识别的对象转换为名称。例如人可通过外观识别怪物，文本观察可以直接提供怪物名称，并可用游戏模型和本地化表取得准确名称；名称不要求已作为画面文字显示。角色、遗物等图标也可按同样原则文本化，但不能附送未展示的效果、后续动作或隐藏对象。
- 保留可见对象及其位置关系和显示状态，不要求把原始图像像素复制进文本响应。模型标识可用于定位和识别，面向阅读时优先提供指定输出语言的名称；当前 JSON 固定使用英语，不切换游戏语言。
- 接口可用操作与画面可见操作分别说明。`available_actions` 随后续工具实现逐步补全，基础观察扩展不要求同步扩展动作列表。

## 选择与查看战场

[选牌接口](development/card-selection.md) 在基础观察报告当前选择；已经展开的候选正文可以直接提供，普通手牌仍按摘要边界处理。完整可浏览候选及悬停解释通过显式详情调用提供。查看战场和返回选牌使用原生眼睛，不自动切换；候选隐藏时不得补出其正文。

## 战后搜刮

[奖励接口](development/rewards.md) 的基础观察只列当前可见奖励行、标题与按钮；完整可浏览奖励和悬停说明需显式查看。尚未打开的卡牌奖励不提前暴露候选。地图或选牌覆盖奖励页时隐藏其内容；空奖励终结页保留真实前进按钮。

## 休息处

[休息处接口](development/rest-site.md) 的基础观察包含当前可见选项及灰置状态；悬停正文通过显式详情调用提供，基础观察仅保留画面已经展开的说明。覆盖时隐藏底层选项，不推测未来随机遗物；升级预览只呈现原生已经显示的牌面。

## 宝箱房

[宝箱房接口](development/treasure.md) 仅在开箱、原生遗物图标已显示后提供遗物名称，悬停效果通过显式详情调用读取。未开箱不读取预生成的隐藏内容；覆盖时隐藏底层宝箱和遗物，空箱不虚构奖励。

## 动作期间事件

`end_turn`、[出牌](development/card-play.md)、[药水](development/potion-actions.md) 和选牌动作可以返回从提交动作到下一可行动阶段、已识别的选择或确认胜负之间已经发生的可感知事件，格式见 [结束回合](development/end-turn.md)。它们放在独立的 `transition` 中，与最终静态观察区分。公开的伤害、牌移动、死亡与复活可以记录；不由内部历史补出隐藏生命值、未展示牌名、牌堆中的未来抽取顺序、未来动作或未发生的随机结果。普通观察调用不回放这些事件，也不因此自动展开手牌与 power 正文。

## 采样与元数据

一次观察的画面与结构化数据应来自同一采样状态。若截图与请求时刻存在悬停、焦点或动画差异，必须说明差异，不能把另一时刻显示的内容补入原观察。

请求 ID、状态令牌、会话标识、去重信息及定位对象所需的标识属于通信或控制元数据，不计作额外的游戏观察。应与面向 LLM 的玩法内容区分；对象名称的文本化按上述规则提供，其他元数据不得额外携带隐藏规则或未来结果。

代码、外部知识或历史记录可以用于核对实现，但不能把由这些来源得出的额外结论伪装成本次直接观察。LLM 自身已有的知识及对已见画面的记忆，与接口本次返回的观察是两回事。

## 当前实现

[观察实现](../spikes/roundtrip/CombatObservation.cs) 结合实际 UI 与模型身份信息，已覆盖基础战斗数值、手牌名称与费用、当前意图、状态图标和顶栏。隐藏内容不以模型数据补齐；覆盖层或过渡期间保守返回不可读状态。字段、空值语义、过滤规则和仍未覆盖的像素遮挡情形统一维护在 [战斗观察 JSON](development/observation.md)。
