# 游戏观察的信息边界

本文记录基础游戏观察的已确认要求。目标是将当前静态画面中的可见游戏信息表达为 LLM 可接受的文本；当前实现与限制见 [战斗观察 JSON](development/observation.md)。当前样本对照见 [战斗画面核对记录](research/2026-10-29-battle-observation-audit.md)，字段来源见 [获取方式调研](research/2026-10-29-observation-data-sources.md)。

## 基础观察

- 以采样时的当前画面为准，覆盖可见的文字、数字、对象外观、图标、计数、牌序、按钮及显示状态。
- 被遮挡、未展开、未悬停的信息不自动补齐。半隐藏手牌可记录可见名称、费用、位置与外框，不能直接附送完整效果、关键词和目标规则。
- 手牌效果后续通过专门的工具或调用查看；本次仅确定其与基础观察分离，尚未设计该工具。
- 基础观察不自动查看其他界面，也不读取未展示的牌堆内容、抽牌顺序、未来随机结果、敌人后续动作或内部状态机。
- “看不见”与数值 0、空集合不同。只有已核对的 UI 规则能够确定含义时，才允许做无信息增益的归一化，例如正常显示且无遮挡的生命条没有格挡标记时记为无格挡。
- 图标不能被静默丢弃，也不能借内部对象信息附送未显示的完整说明。可以保留当前图像或对应图标的可见语义；无法仅从当前画面确定的含义应保留未知。
- 允许将外观可识别的对象转换为名称。例如人可通过外观识别怪物，文本观察可以直接提供怪物名称，并可用游戏模型和本地化表取得准确名称；名称不要求已作为画面文字显示。角色、遗物等图标也可按同样原则文本化，但不能附送未展示的效果、后续动作或隐藏对象。
- 保留可见对象及其位置关系和显示状态，不要求把原始图像像素复制进文本响应。模型标识可用于定位和识别，面向阅读时优先提供指定输出语言的名称；当前 JSON 固定使用英语，不切换游戏语言。
- 接口可用操作与画面可见操作分别说明。`available_actions` 随后续工具实现逐步补全，基础观察扩展不要求同步扩展动作列表。

## 采样与元数据

一次观察的画面与结构化数据应来自同一采样状态。若截图与请求时刻存在悬停、焦点或动画差异，必须说明差异，不能把另一时刻显示的内容补入原观察。

请求 ID、状态令牌、会话标识、去重信息及定位对象所需的标识属于通信或控制元数据，不计作额外的游戏观察。应与面向 LLM 的玩法内容区分；对象名称的文本化按上述规则提供，其他元数据不得额外携带隐藏规则或未来结果。

代码、外部知识或历史记录可以用于核对实现，但不能把由这些来源得出的额外结论伪装成本次直接观察。LLM 自身已有的知识及对已见画面的记忆，与接口本次返回的观察是两回事。

## 当前实现

[观察实现](../spikes/roundtrip/CombatObservation.cs) 结合实际 UI 与模型身份信息，已覆盖基础战斗数值、手牌名称与费用、当前意图、状态图标和顶栏。隐藏内容不以模型数据补齐；覆盖层或过渡期间保守返回不可读状态。字段、空值语义、过滤规则和仍未覆盖的像素遮挡情形统一维护在 [战斗观察 JSON](development/observation.md)。
