# 游戏观察的信息边界

本文记录基础游戏观察的已确认要求。目标是让 LLM 获得与当前静态画面相同的信息；这些要求尚未全部落实到现有原型。当前样本对照见 [战斗画面核对记录](research/2026-10-29-battle-observation-audit.md)。

## 基础观察

- 以采样时的当前画面为准，覆盖可见的文字、数字、对象外观、图标、计数、牌序、按钮及显示状态。
- 被遮挡、未展开、未悬停的信息不自动补齐。半隐藏手牌可记录可见名称、费用、位置与外框，不能直接附送完整效果、关键词和目标规则。
- 手牌效果后续通过专门的工具或调用查看；本次仅确定其与基础观察分离，尚未设计该工具。
- 基础观察不自动查看其他界面，也不读取未展示的牌堆内容、抽牌顺序、未来随机结果、敌人后续动作或内部状态机。
- “看不见”与数值 0、空集合不同。只有已核对的 UI 规则能够确定含义时，才允许做无信息增益的归一化，例如正常显示且无遮挡的生命条没有格挡标记时记为无格挡。
- 图标不能被静默丢弃，也不能借内部对象信息附送未显示的完整说明。可以保留当前图像或对应图标的可见语义；无法仅从当前画面确定的含义应保留未知。
- 画面没有显示的正式名称不能冒充画面文字。对象的可见外观与通过外观识别出的标签应区分；不能直接把内部模型名、源码类型或资源路径当作额外玩法知识提供。
- 接口可用操作与画面可见操作分别说明。原型只支持 `end_turn`，不意味着玩家画面上只有结束回合这一种操作。

## 采样与元数据

一次观察的画面与结构化数据应来自同一采样状态。若截图与请求时刻存在悬停、焦点或动画差异，必须说明差异，不能把另一时刻显示的内容补入原观察。

请求 ID、状态令牌、会话标识、去重信息及定位对象所需的不透明标识属于通信或控制元数据，不计作额外的游戏观察。应与面向 LLM 的玩法内容区分，避免借标识泄露对象内部类型或隐藏规则。

代码、外部知识或历史记录可以用于核对实现，但不能把由这些来源得出的额外结论伪装成本次直接观察。LLM 自身已有的知识及对已见画面的记忆，与接口本次返回的观察是两回事。

## 当前实现

[原型观察实现](../spikes/roundtrip/GameAdapter.cs) 已返回角色、生命、能量、手牌模型标识、敌人模型标识和部分牌堆计数。它缺少多项可见 UI 信息，也未将内部模型标识与画面内容分离，因此尚不满足本规范。后续调整必须同时检查信息缺失和额外信息暴露，不能仅靠增加字段完成。
