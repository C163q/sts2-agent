## 原生奖励与收尾

证据位于上述程序集的以下成员；本次反编译保留在 Git 忽略目录 `.tmp/2026-10-31-rewards/source/`，不纳入仓库。

| 类型与成员 | 已核实行为 |
| --- | --- |
| `Rewards.RewardsSet.WithRewardsFromRoom`、`GenerateWithoutOffering`、`Offer` | 战后奖励包含普通奖励及 `CombatRoom.ExtraRewards`；奖励会经过原生 hooks、生成、排序与同步。最后一幕 Boss 默认没有普通掉落，但仍可打开终结奖励页 |
| `Nodes.Screens.NRewardsScreen._Ready`、`UpdateScreenState` | 每行由 `NRewardButton` 或 `NLinkedRewardSet` 表示；标题区分 Loot 与 Mugged。终结页拿完后只淡出列表并把 Skip 改为 Proceed，不立即销毁整个屏幕 |
| `Nodes.Rewards.NRewardButton.GetReward` | 原生点击先 Disable，再经 `RewardsSetSynchronizer.SelectLocalReward` 领取；成功发 `RewardClaimed`，未领取则重新 Enable 并发 `RewardSkipped` |
| `Rewards.PotionReward.OnSelect` | 满槽为未领取；不会自动替换现有药水 |
| `Rewards.CardReward.OnSelect` | 进入原生候选页，同步选择并处理卡牌或替代选项；返回值决定奖励是否完成，卡牌 Skip 不一定移除奖励入口 |
| `NCardRewardSelectionScreen.DisableCardsForShortTimeAfterOpening`、`RefreshOptions` | 防误点禁用卡牌 0.35 秒，牌面入场 tween 为 1 秒；仅观察 JSON 安静 250ms 可能过早返回 |
| `Models.Relics.Whetstone.AfterObtained` | 从领取当时牌组可升级攻击牌中随机选取至多两张升级，因此先拿卡牌和先拿遗物可能有不同结果 |
| `NRewardsScreen.OnProceedButtonPressed` | 普通终结奖励、Boss、胜利房间和非终结奖励使用不同原生分支；不能把前进强制实现为地图打开 |
| `Runs.RunManager.ProceedFromTerminalRewardsScreen` | 普通情况打开地图；特定事件战斗恢复父事件。真正离开房间时才由同步器处理剩余奖励 |
| `NMapScreen.Open`、`NOverlayStack` | 奖励阶段可经实际可用的顶栏入口查看地图；覆盖奖励内容，不能透过地图点击奖励 |

`RewardCompatibility` 的适配依据是目标版本 `NLinkedRewardSet.Reload`：它将无参数的 `Callable.From(GetReward)` 连接到携带一个 `NRewardButton` 参数的 `RewardClaimed` 信号。本次图形测试复现金币已领取、Godot 抛 `Expected 0 argument(s), received 1`、互斥组留在页面并超时。适配只在模型属于对应互斥组、连接委托确实指向该组的无参数 `GetReward` 时，换成忽略信号参数的包装，调用原生收尾；不替代奖励同步或直接写金币。

## 偷窃与逃离

- `Models.Powers.SwipePower.Steal` 移除牌组中的对应牌；持有者死亡时 `BeforeDeath` 添加 `SpecialCardReward`，并设置 `ThievingHopperWeak` 的自定义追回描述。正常卡牌三选一和追回固定牌不是同一种奖励。
- `SurprisePower.AfterDeath` 在佣兵死亡时召出后续敌人，将 `ThieveryPower` 累积的被偷金币转为胖地精的 `HeistPower`；`HeistPower.BeforeDeath` 才添加 `GoldReward(...wasGoldStolenBack: true)`。不能假设杀死佣兵就直接返还所有金币。
- `EncounterModel.CalculateGoldProportion` 默认按未逃离敌人的比例计算普通金币；`GremlinMercNormal.CalculateGoldProportion` 有专门规则：胖地精未逃跑为完整比例，逃跑但没有偷到钱为一半，偷到钱再逃跑为零。普通奖励生成还会按比例决定金币条目；新手引导可用固定预设覆盖常规掉落，本次隔离全部逃离仍出现普通金币的复现即属于该分支，不能概括为“逃跑一定没有金币”；卡牌、药水与额外追回条目各自走原生规则。
- 工具只读取已经显示的奖励和标题，不额外输出被偷物品内部记录、逃离的隐藏奖励清单或尚未打开的候选。

## 接口决定

采用 `claim_reward(reward_id)`、`proceed()` 和只读 `inspect_rewards()`。搜刮行与卡牌候选有不同身份、生命周期和跳过语义；只有点开奖励后才复用选牌工具。逐项执行保留模型对领取顺序和取舍的控制。基础观察新增 `scene: rewards`、可选 `rewards`，底层 schema 为 `6`。领取单独报告 `claimed/not_claimed/pending`，不将原生拒绝误报为已取得物品。

## 本次验证

证据保留在 `.tmp/2026-10-31-rewards/`；阶段性失败日志保留用于对照。

- Python 全套 182 项；包含真实 stdio 分派、非法参数、坏响应、隐藏内容、递归投影、领取结果和动作许可。C# 全套 22 项，包括新增的手动处理分类对照。最终构建零警告、零错误。
- 十一种图形 MCP 场景通过：`nested-verified.json`、`returned-verified.json`，以及 `*-verified2.json` 中的 escaped、unsupported、card_first、relic_first、basic、full、skip、empty、linked。每次使用独立启动的测试实例和自己的截图目录，不操作正式对局。
- basic 覆盖真实奖励列表滚动、地图遮挡与返回、稳定奖励 ID、卡牌跳过后重开、选牌领取、固定卡牌、金币、药水、遗物、领取完毕后前进。full 覆盖满槽未领取、主动丢弃后领取；linked 验证互斥组只获得所选项。
- 磨刀石顺序用只有一张防御的隔离牌组消除随机歧义：先拿愤怒后拿遗物得到 `Anger+`，反向则得到 `Anger`。不直接把牌改为升级以制造测试结果。
- returned/escaped 使用原生 `SwipePower`、`HeistPower` 和 `CreatureCmd.Escape` 钩子构造结果，验证追回条目、标题和实际掉落；没有完整重演草蜢或佣兵全部 AI 回合。escaped 初版断言遗漏新手预设分支，修正为核对原生逃离记录、比例为零及没有追回条目，不要求普通预设金币消失。
- 嵌套奖励先复现超时，再修复多层奖励页面识别与父任务等待；随后截图发现大卡预览遮挡，`preview_cards` 断言再次复现并修复。最终 nested 要求原生大卡预览已结束，并成功跳过下层奖励返回上层前进。
- 最终 `chain-final.json` 回归通过原有真实图形 MCP 的一次观察连续十动作、外部状态过期及查看页许可；`manual-final.json` 再次验证最终构建遇到 Astrolabe 未支持选择及时返回手动处理。
- 独立审阅发现一项 Important：未知窗口和未支持父房间未完整分类；已修复为 `RewardBoundary` 正向判定，并加入分类对照及 Astrolabe 未支持选择的图形检查。没有遗留审阅问题。
