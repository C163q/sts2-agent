# 地图返回预设与前瞻子图验证

## 范围和语义

代码基线 `961d160`，MCP 从 `0.29.1` 更新为 `0.30.0`。Mod 保持 `0.34.2`，不新增游戏 API 调用、原生字段或读取来源；使用既有已校验的当前幕地图，在 Python 输出层投影。完整参数规则由[地图接口](../development/map-inspection.md#返回范围参数)维护。

默认全图输出保持原样。`preset=selectable` 提供当前候选详情，优先于 `max_steps`；后者取正值时按实际有向连线生成 N 步以内的子图，保留当前节点并剪掉指向子图外的边。尚无当前节点时以最低行作为第 1 步。飞鞋无连线候选与连线可达性分别表达，原生候选和已走路线作为上下文保留，不预测未来特殊选路。

参数在 IPC 前校验；参数错误保留此前许可。成功读取先校验全图再裁剪，过滤区域中的坏数据也必须使整个响应失败且清除许可。原生仍接收无参数 `inspect_map`；失败或未知结果不自动重试。

测试基线为 Linux 游戏 `v0.107.1`（发布提交 `59260271`）、RitsuLib `0.6.10`。使用已有隔离运行时，Mod DLL SHA-256 为 `862e6b411ec203275560eb98af26d3228f97a2f9a8e0222c70ba83c4a1064a68`；本次不重新编译 C#。

`.tmp/2026-11-01-map-presets/suite.json` 包含四项 `verify_map_presets.py` 场景及原有地图详情直接旅行场景：飞鞋无连线候选、战斗零候选、新幕起点、第二 Boss。每次对照原生全图检查 1/2/3 步子图、预设优先级、重复读取不改变指纹，并使用保存的 MCP 许可直接继续原生动作。专用验证器全程不调用 `get_observation`，自行保存截图，不需要外部截图。

独立审阅发现并已处理旧验证器的页面状态断言，以及累计集合重复复制的性能问题；遍历使用原地集合更新，按图节点和边数量线性执行。另补多最低行起点和排队动作不能借用未来读取许可的回归。未操作正式存档或替换正式安装，不覆盖整局自动通关及任意第三方地图规则。
