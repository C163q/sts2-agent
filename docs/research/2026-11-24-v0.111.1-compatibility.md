# v0.111.1 正式版差异与兼容验证

对照 Linux Steam 测试版 `v0.111.0`（`41cef1ea`，build `24724944`）与正式版 `v0.111.1`（`cc1f9462`，build `26655341`）。[正式版公告](https://store.steampowered.com/news/app/2868840/view/708914425087656392)汇总了 v0.108.0 至 v0.111.0 的改动，以下差异以先前归档的 v0.111.0 为起点。

| 对照项 | 结果 |
| --- | --- |
| 游戏文件 | 两版各有 222 个文件（排除 `mods/`），SHA-256 仅有三处不同：`release_info.json`、`sts2.dll` 和 `SlayTheSpire2.pck`。可执行文件、GodotSharp、Harmony、SmartFormat 和 `sts2.xml` 一致。 |
| 游戏程序集 | ILSpy 的 IL 导出逐字节一致。3,536 个反编译 C# 文件中，仅 `Properties/AssemblyInfo.cs` 的 `AssemblyInformationalVersion` 构建提交变化。 |
| 资源包 | 12,449 个原有条目内容摘要一致，新增 `localization/eng/patch_notes/2026_11_13.md`。 |

Mod 构建和隔离实例转用正式版及 RitsuLib 0.6.15。RitsuLib 仍以 `0.111.0` 标记该系列兼容目标，游戏日志确认 `Host=v0.111.1; runtime=0.111.0`。Mod 0.87.1 的清单要求游戏至少为 0.111.1。MCP 维持 0.89.1、观察 schema 维持 50。[RitsuLib 0.6.15 发布页](https://github.com/BAKAOLC/STS2-RitsuLib/releases/tag/v0.6.15)

隔离准备脚本按完整包替换 RitsuLib，以清理 0.6.10 中已移除的 `compat/0.109.0` 与 `compat/0.110.0`。重跑准备后，隔离实例的 38 个 RitsuLib 文件与创意工坊安装逐一核对 SHA-256。

## 建筑师验证修正

建筑师夹具可直接跳到第三幕终点，初始进度缺少铁甲战士的统计记录。原生 `NGameOverScreen.SaveBadgesToProgress` 通过角色 ID 读取统计，缺少记录时抛出 `KeyNotFoundException`，导致继续动作超时。旧 v0.111.0 的 `acceptance-2/run_ending_architect_proceed` 回执也记录了 `timeout`，当时验证器未核对该动作是否完成。

第三幕终点夹具复用游戏的 `ProgressState.GetOrCreateCharacterStats` 初始化角色统计。验证器要求 Continue 返回完成回执，并用 `inspect_run_result` 确认进入汇总页。该调整限于隔离测试。

## 证据位置

本地对照材料位于 `.tmp/2026-11-24-v0.111.1/`，其中 `game-file-diff.json`、`source-diff.json` 和 `pack-diff.json` 分别记录文件、反编译和资源差异。原始 v0.111.0 环境见[迁移调查](2026-11-10-v0.111-migration-investigation.md)。

- `build-final.log` 记录 0 警告、0 错误的构建。870 项 Python 检查和 155 项 C# 检查通过，分别见 `python-final.log` 和 `csharp.log`。
- `gui-final/report.json` 中计入通过的 8 个用例，覆盖战斗观察、出牌和用药、保留和消耗手牌、灾厄胜利后奖励续接、Beautiful Bracelet 附魔、Sere Talon 致死提示及充能球事件。该轮建筑师用例按旧断言误标通过。
- `gui-architect-retest/report.json` 记录最终产物上的建筑师和战斗读取复测。Continue 返回 `action_completed`、`complete:true`，随后读到 `summary`。两轮合计验证 9 个不同场景。完整对局、多人和音频不在本次验证范围。
