# 动作返回与牌堆界面更新

## 基线与根因

2026-10-30，基线提交 `2b6b16a`、Mod `0.17.0`、MCP `0.14.0`，Linux 游戏 `v0.107.1` / 分支 `v0.107.1` / 提交 `59260271`，RitsuLib `0.6.10`。本次修复为 Mod `0.18.0`，保留工具、参数与返回字段。

用户实战反馈：打击返回 `complete=true/player_ready`、伤害与能量变化正确，弃牌可见计数仍为 0；没有其他操作，稍后变为 1。独立图形游戏通过真实 stdio MCP 复现了同一问题。根因是逻辑动作结束与牌堆计数的显示更新分离，原有字符串连续 250 毫秒不变的检查无法识别尚未落地的飞牌。

目标游戏目录 `data_sts2_linuxbsd_x86_64/sts2.dll` 核对的类型与成员：

| 原生成员 | 核实行为 |
| --- | --- |
| `PlayCardAction.ExecuteAction`、`CardModel.OnPlayWrapper` | 等待卡牌逻辑、入结果堆及牌后 hooks，随后结束原生动作 |
| `CardPileCmd.Add` | 先修改逻辑牌堆，再创建独立飞牌；未等待飞牌完整生命周期 |
| `NCardFlyVfx.PlayAnim`、`NCardFlyShuffleVfx.PlayAnim` | 首段飞行结束才调用 `InvokeCardAddFinished`，后续继续收尾并释放节点 |
| `NCombatCardPile.Initialize/AddCard/RemoveCard` | 可见计数由牌堆完成通知更新，未必同步于逻辑列表 |
| `NCardFlyPowerVfx.PlayAnim` | 有限的能力牌飞行动画，结束后释放节点 |

本项目基础观察读取实际 `CountContainer/Count` 标签，保持静态画面的可见信息边界；本次不把内部逻辑数量提前输出，也不改写计数或加快动画。

## 修复与公共语义

`GameAdapter.ActionObservation` 统一出牌、药水、选牌后继续及结束回合的等待。`ActionSettling` 校验停止原因、观察内容和牌动画条件是否持续满足；正常可行动、战斗外药水完成及取消返回须等待已核对的飞牌节点退出，再确认 250 毫秒观察稳定。原因或条件改变则重置，不沿用较早出现过的正常边界。帧正常推进时，25 秒内不能完成则返回 `timeout/complete=false`。

`choice_required` 仍在等待玩家输入处返回，不等待父动作完成或所有飞牌；胜负和战斗替换保留各自边界。公共 MCP 提示明确 `complete` 确认的是本次交互边界，等待选择的效果和装饰动画可以尚未结束。完整契约只在[结束回合接口](../development/end-turn.md#动作完成与画面稳定)维护。

原有文档虽定义了正常停止边界，却没有说明独立飞牌仍可改变公开计数；实现也没有等待它们。因此这是实现缺陷，不能只通过放宽 `complete` 的解释解决。本次同时修复等待判定并说明保证范围。详细问题报告保存在忽略目录 `.tmp/2026-10-30-action-settling-report.md`。
