# 手牌详情接入 MCP

当前状态：已完成。工具、回归检查、真实 stdio MCP 的正式战斗只读验证和独立审阅均完成，文档已同步。无需更新 Mod 或游戏进程，用户禁用的 Codex MCP 配置保持不变。

## 范围与契约

- MCP server `0.2.0`，官方 Python SDK 仍为 `mcp==1.26.0`；游戏 `v0.107.1`、Mod `0.4.0`，复用已验证的文件操作，不增加游戏 API。
- 新增无参数只读工具 `inspect_hand()`，直接返回 [共享提示格式](../development/hand-inspection.md) 的 `hand`、`hover_tips` 和适用的 `notes.card_values`，不附送敌人意图或 `available_actions`。
- 无须先观察即可查看手牌，但查看不会授予动作权限。已有战斗观察令牌仅在查看返回相同 `snapshot_id` 时保留；状态变化、失败或取消时清除，不以手牌响应的新令牌自动授权动作。
- 使用同一串行锁、懒获取控制锁和错误过滤；握手与工具发现仍不占控制锁。另一个连接持有控制权时，查看手牌也返回 `controller_busy`，不发送游戏请求。
- 先验证旧实现缺少工具及方法，再实现；新增检查覆盖直接查看、未变或已变令牌、失败、取消、只读标记、严格参数、共享提示格式及控制锁竞争。

## 验证结果

- 28 项 Python 回归通过，包含真实 stdio MCP 及临时文件 IPC；现有结束回合、重复请求阻止、失效令牌和预热握手行为未回归。
- 正式战斗的真实 stdio MCP 验证通过，server 为 `0.2.0`，发现三个工具；依次仅调用 `inspect_hand → get_observation → inspect_hand`，两次手牌结果一致且与基础观察的 ID 相同。未调用动作工具。
- MCP 采样包含当前 5 张手牌，文件为 `.tmp/live/mcp-hand-inspection.json`；初始化、工具定义、调用响应及原始前后观察为 `.tmp/live/mcp-hand-evidence.json`。读取前后观察令牌一致，临时 MCP 进程退出后释放控制锁。
- 独立审阅未发现目标正常协议下的阻断；另补强两项异常边界，并各自先验证失败再修正：手牌工具仅转换 `state.hand`，即使上游意外带上敌人或动作也不透传；畸形卡牌或提示元素形成统一 `transport_error`，不逃逸为内部异常。
- 持续维护文档已同步工具目录、版本前提、令牌策略、控制锁时机及只读验证命令；未更改游戏 Mod 或用户配置。已有连接需要重新加载 server 脚本，手动禁用的连接仍由用户自行启用。
