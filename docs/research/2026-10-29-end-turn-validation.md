# 结束回合事件与 RitsuLib 接入验证

## 实现基线

基于项目 Git `b55ea33` 实施，交付版本为 Mod `0.13.0`、MCP server `0.10.0`。现行接口见 [结束回合](../development/end-turn.md)，设计和程序集证据见 [调研](2026-10-29-end-turn-events.md)。

- 游戏：Linux `v0.107.1`，分支 `v0.107.1`，提交 `59260271`。安装目录内 `data_sts2_linuxbsd_x86_64/sts2.dll` 的 SHA-256：`d13f3f150b1413b24c3a9c5575cdf5398dc74270877d55dec9a556dd8150bd03`。
- RitsuLib：上游提交 [`772f280964f2efc7c7e2f29fc59844e68616dd57`](https://github.com/BAKAOLC/STS2-RitsuLib/commit/772f280964f2efc7c7e2f29fc59844e68616dd57)，官方 `0.6.10` 发布的 `0.107.1` 兼容 ZIP；已按发布清单校验 SHA-256，值及配置方式见 [构建指南](../development/roundtrip.md#前提与构建)。
- 工具：.NET 9，Python `3.14.8`，MCP Python SDK `1.26.0`。游戏线程负责采样及动作，外部 Python 负责协议和等待。

使用完整 RitsuLib 运行时及其上游引用配置，不提交第三方二进制，不复制到正式游戏安装目录。隔离实例的库位于 `.tmp/roundtrip/runtime/mods/STS2-RitsuLib/`，个人路径通过 `RitsuLibDir` 配置。RitsuLib 本身还会初始化其他框架能力，并非仅加载事件模块。

## 实现结果

保留 12 个 MCP 工具及无参数 `end_turn()` 调用，动作响应新增 `transition`，包含事件、停止原因与完整性标志。首次遇到已识别的本地选择时返回，不代选；胜负使用原生结束事件判断，不以 HP 暂时为零判断。

RitsuLib 的出牌、生成牌和角色加入通知，与原生历史、牌堆及角色事件组合使用。抽牌采用原生历史写入时机，弃牌与消耗采用原生入堆时机，避免后置钩子造成倒序。伤害补录覆盖本次验证中的致命一击；生命数字隐藏时不输出内部绝对值或可反推出内部 HP 的实损值。对 power 使用公开显示计数，无数字图标不附送内部层数。

### 隔离游戏实例

无头模式共 `14` 个场景、`15` 次实际结束回合，均返回预期边界且未截断。复活场景跨回合收集死亡及后续复活证据。

| 场景 | 验证内容 |
| --- | --- |
| `normal` | 普通回合、公开塞入 Slimed、下一回合抽牌 |
| `wither` | 凋萎实际伤害与卡牌来源 |
| `wither_death` | 凋萎导致战斗失败，保留伤害与死亡事件 |
| `enemy_death` | 敌方致命攻击，保留最后一击并确认失败 |
| `tyranny` | 下一回合暴政选择出现时返回 `choice_required` |
| `retain_choice` | 计划妥当在当前回合结束阶段要求选择时返回 |
| `boulder` | 滚石在回合开始期间击杀，返回胜利 |
| `doom` | 灾厄直接处决、来源及胜利，不伪造普通伤害 |
| `stampede` | 惊逃自动打出 Thunderclap，保留来源与致命伤害 |
| `revive` | 残杀千足虫死亡后复活，保持同一实例标识 |
| `blocked` | 普通直接攻击全部被格挡，实损为零 |
| `hellraiser` | Hellraiser 抽牌触发自动出牌，抽牌事实先于自动出牌 |
| `exhaust_block` | 虚无牌消耗触发 Feel No Pain，消耗事实先于格挡 |
| `hidden_hp` | 无数字无限生命显示下，日志不输出隐藏的绝对 HP |

另在图形窗口中验证 `tyranny` 与 `hidden_hp`。检查暴政截图时，游戏已显示 `Choose a card to Exhaust.`，结束回合按钮不可用，工具已经返回且未选择任何牌。

真实 stdio MCP 连接图形实例完成往返验证，实际握手版本为 `0.10.0`、目录保持 `12` 个工具；确认文本 JSON 与 `structuredContent` 相同、战报可读、非法参数和缺少/重复/过时动作令牌被拒绝，普通观察读回不重复附送历史事件。

各场景的新日志未发现 `[ERROR]`、未处理异常或生命周期观察回调失败。仍存在既有无头 FMOD/渲染警告，以及 RitsuLib 对 Steamworks 类型枚举的兼容性警告；声音不在验证范围。

## 独立审阅及回归修复

独立只读审阅指出两项重要问题，均先以实际游戏场景复现，再修复并验证：

1. RitsuLib 后置通知会把抽牌、消耗放在其触发效果后面。`hellraiser` 和 `exhaust_block` 先失败；改用原生生效点后均通过。
2. 原生 HP 变化可能绕过无数字生命条的信息边界。`hidden_hp` 先失败；增加公开数字判断及未知实损投影后通过。

另确认 `PowerModel.SetAmount(silent: true)` 仍能更新显示，记录器因此监听显示值变化并去重，不把 `silent` 当作不可见。

保留一项已声明的局限：Osty 代受伤分支可能漏掉原目标的格挡记录。当前不宣称复杂召唤战斗的完整伤害核算，未在本次补齐该分支。
