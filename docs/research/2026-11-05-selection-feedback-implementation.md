## 实现

- `SelectionAvailability` 独立诊断没有选择、不可用类型、战场查看、覆盖、确认预览、整包／结果页、无效候选和未就绪状态。`select_card` 先核对快照，再在尚未定位／点击时使用既有动作未提交保证；错误说明为固定公开文本。
- `SelectionInputJournal` 在真实持牌器信号周围保存原选择集合与同次快照的公开卡牌身份，预留事件位置后才执行原生输入。原生立即提交时仅以原选择任务的成功结果确认接受，不从后续页面推断选择，不等待未完成任务。
- 选中／取消使用公共 `card_selected/card_deselected`。手牌替换先取消旧牌再选中新牌；最后一张自动提交保留选中，后续效果使用同一缓冲顺序。返回确认预览只包装 `cancel_preview`，页面清理和确认不记取消；卡包操作不作为单张选择。
- 拒绝和原生没有改变选中集合时不产生反馈。名称不可读时保持 `null`，未知牌的公开占位文字保持原样；原候选 ID 在输入前固定，避免进入下一战斗后的 ID 重置影响已记录的选择。事件投影拒绝已知但无关的玩法字段，继续过滤未知私有字段。
- 复用既有有界缓冲，不增加全局订阅；定位点击仍由 `SelectionActions` 负责。交互后的失败公开固定安全说明，保留必须重新观察的边界。

## 实施取舍

- 延续已有临时分支、当前检出目录和隔离运行时，只有一个实施者；测试各自使用独立进程与存档，控制提交范围，未另建 worktree。
- 用户确认设计后持续实施，不重复确认执行方式；两个代码任务共用适配器及端到端断言，合为一个验证后的实现提交。
- 采用局部输入包装和既有动作未提交保证，避免增加全局订阅或扩展共用会话策略。交互后失败与过期／未知结果仍要求观察。
- 保持未知私有字段的既有过滤规则；仅严格限制选中事件的公开玩法字段，不将整个解析器改成原始键严格拒绝。
- 多张比较不从结果克隆或历史缓存补原牌名称；名称不可读则保留 null，原生公开的 Unknown 占位文字可保留。取消后仍可按原 ID 读取候选。
- 只修正测试夹具的标题设定和战后清理等待，不扩大游戏工具的稳定边界；生产代码未变的已通过场景不重复运行，最终产物另做相关加载和行为检查。

## 验证边界

选中事件只提供原候选的公开身份和 UI 变化，不增加正文、费用、随机结果或牌堆位置。控制器输入、任意第三方选择页面和真实跨局竞争不在实测范围；不会因此改变已有参数或卡包语义。`selection_option` 的取消预览只接入共享事件，其他按钮及 `set_selection_view` 的完整工具审阅仍留在各自条目。
