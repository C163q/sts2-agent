# use_potion 审阅与待确认事项

> 当前状态：五项用药问题及地图 covered 已实现并验证，use_potion 已完成审阅。已检查 30 类情况，整理了 [120 份完整返回](2026-11-04-use-potion-examples/README.md)。源码、问题编号及测试细节另放在[开发核验记录](2026-11-04-use-potion-development-notes.md)。

## 已确认的修改范围

现有参数已经够用：选择药水槽位，需要时指定目标；保留 default/full。成功返回也已经很短，暂时没有增加 summary 的必要。已确认处理下面五项。以下说明修复前的表现及确定的处理方向，实现及验证见[实施记录](2026-11-05-potion-actions-implementation.md)。

### 1. 出错时说明具体原因

现在，空槽、忘填目标、目标不合法、自动药水不能手动喝等情况，大多都只说“当前无法执行”。LLM 很难知道应该改参数、完成选牌，还是关闭页面。

建议直接说明实际原因，例如“该药水槽为空”“这瓶药水需要指定目标”“请先完成当前选牌”。

### 2. 没有执行任何操作时，允许直接改做别的事

例如，因目标填写错误而用药失败后，游戏没有变化，但 LLM 再调用 end_turn，仍会被要求先查看当前状态。选牌期间误调用用药，也会让后续选牌多出一次查看要求。

建议：确认没有执行任何操作时，允许直接纠正请求或选择其他操作。超时、连接中断等无法确认结果的情况仍应先查看，避免重复用药。

### 3. 明确药水槽位编号始终按原药水栏计算

药水槽位从左到右、从 0 开始，空槽也占位置。筛选后返回的第一瓶药水，不一定在第 0 槽。

例如，只查看第 1 槽时，返回中与位置有关的字段是：

```json
{
  "slot_indices": [1],
  "potion_slots": [{"name": "Block Potion"}]
}
```

这里用药仍应传 `"potion_slot": 1`。建议把这个规则写进参数说明，避免 LLM 按筛选后数组的位置选错药水。

### 4. 将目标查看描述为提示，不暗示必须先调用

简洁表达可以是：**“提示卡牌或药水可指定的目标。”** 英文提示词可写为：

```text
Show targeting hints and usability for a hand card or potion.
```

如果 LLM 已经知道当前可用的目标 ID，就能直接使用；不确定时再调用 inspect_targets。用药的 target_id 参数只需说明“需要指定目标时填写，否则省略”，不要把它写成只能来自某个查看工具的结果。

### 5. 一瓶药水不能操作，不应影响其他槽位或漏掉实际发生的用药

测试中，把一个槽位设为不能点击或悬停后，其他正常槽位也被一起禁止使用。把槽位移到屏幕外也会产生同样影响；这些都是测试人为设置的条件，没有发现正常游玩会出现这种布局。

还复现了更直接的问题：禁用格挡药水所在的槽位后结束回合，另一槽位的瓶中精灵实际消耗、玩家被救回，但返回的事件列表里没有记录瓶中精灵的使用。

建议分别判断每个槽位能否操作；记录实际发生的变化时，以玩家是否能看到为准，不能因为某个槽位不能点击，就漏掉其他药水的变化。

## 地图与牌组显示状态的差异

两个场景都是：**正在战斗，然后打开另一个页面，战斗被挡在下面。** 以下是修复前实测返回中 scene 和 screen 两个字段的摘录，其他字段未展示。

打开牌组时：

```json
{
  "scene": "combat",
  "screen": {
    "status": "covered",
    "view": "deck"
  }
}
```

打开地图时：

```json
{
  "scene": "combat",
  "screen": {
    "status": "visible",
    "view": "map"
  }
}
```

差异在于 **status 描述的对象不一致**：牌组的 covered 表示“下面的战斗被覆盖”，地图的 visible 却表示“地图本身可见”。scene 都是 combat，分别用 view 表示打开了牌组或地图，这两点是一致的。

这不代表打开地图后仍能出牌或用药；这些操作目前会被正确拒绝。问题是同一个 status 字段容易被读成不同含义。

**建议统一表示下面的场景是否被覆盖。** 按这个方案，战斗中打开地图应改成：

```json
{
  "scene": "combat",
  "screen": {
    "status": "covered",
    "view": "map"
  }
}
```

地图的 screen.status 已统一为 covered；inspect_map 的其他设计及 get_observation.map 内容仍待后续审阅。开发依据见[地图相关记录](2026-11-04-use-potion-development-notes.md#关联发现地图上下文)。
