## 原生流程证据

反编译证据保存在不纳入 Git 的 `.tmp/2026-10-31-treasure/source/`，类型均位于 `MegaCrit.Sts2.Core`：

| 类型与成员 | 已核实行为 |
| --- | --- |
| `Rooms.TreasureRoom.EnterInternal` | 创建房间 UI、执行 `Hook.AfterRoomEntered`，随后 `BeginRelicPicking`；此时同步器可能已生成遗物，关闭宝箱的观察不得读取 |
| `Nodes.Rooms.NTreasureRoom.OnChestButtonReleased/OpenChest` | 原生开箱按钮只执行一次并禁用；先正常奖励、后额外奖励，再显示遗物集合；金币无需额外点击 |
| `Multiplayer.Game.OneOffSynchronizer.DoTreasureRoomRewards` | 遵守 `ShouldGenerateTreasure`；正常金币由原生奖励 RNG 及进阶规则计算，另处理 Spoils Map；工具不预测或补发 |
| `Rooms.TreasureRoom.DoExtraRewardsIfNeeded` | 为每名玩家生成额外奖励，等待本地奖励界面关闭后继续开箱；不能从外部等待整个父任务结束才返回 |
| `Nodes.Screens.TreasureRoomRelic.NTreasureRoomRelicCollection.InitializeRelics/AnimIn` | 实际无遗物时走空箱 VFX；有遗物时入场动画结束才允许鼠标点击；单人 holder 的 index 为 0 |
| `NTreasureRoom.OpenChest/EnableSkipAfterDelay` | 单人显示 Skip 并有延迟；领取后等待原生集合完成，改成 Proceed 并允许地图旅行；不是必须领取遗物才能离开 |
| `NTreasureRoom.OnProceedButtonPressed` | Skip 调用同步器跳过并进入原生终结奖励前进流程，普通 Proceed 同样沿用原生流程；工具不强制打开地图 |
| `NTreasureRoomRelicCollection.PickRelic` 与 `GameActions.PickRelicAction` | 原生 UI 提交 `PickRelicLocally`，由动作同步器入队执行；工具通过 holder 点击进入流程，不直接授予遗物 |
| `NTreasureRoomRelicCollection.AnimateRelicAwards` | 使用 `TaskHelper.RunSafely(RelicCmd.Obtain(...))` 后完成 UI 任务，没有等待遗物自身效果；仅看 UI 和动作队列为空不足以确认结算完成 |
| `Commands.RelicCmd.Obtain(RelicModel,Player,int)` | 添加遗物后等待 `AfterObtained`；适配层只观察返回任务，不替换原生流程；换局后丢弃旧局任务引用，防止旧局未完成任务阻塞新宝箱 |
| `Models.Relics.SilverCrucible.AfterRoomEntered/ShouldGenerateTreasure` | 进入宝箱房累计次数；第一次宝箱房不生成普通金币与遗物，第二次及以后恢复正常 |

多人共享遗物涉及所有玩家投票及可能的争抢流程；当前 `loot_treasure` 仅允许实际一名玩家。原生教程对话由人工处理边界报告，不强行确认。

## 实现决定

默认 `loot_treasure` 合并开箱与领取唯一单人遗物，满足一次调用完成正常宝箱的要求。可选 `open_only` 保留先看遗物再决定的空间，`proceed` 保留原生跳过能力。组合动作只在同房间、暴露且就绪时执行第二次点击，两段共享总等待预算；出现额外奖励、选择或对话即返回，不保存跨调用自动领取意图。

`RelicObtainTracker` 对已核实的具体 `RelicCmd.Obtain` 重载增加观察性 postfix，保存原始任务及所属本次游戏引用，仅用于等待；选择与奖励边界优先于未完成父任务。等待不会阻塞游戏线程，也不会等待 LLM 输入。

静态观察依据真正显示的 holder 与图标，不根据同步器未来内容推测奖励。关闭和遮挡状态不输出遗物名；悬停说明仅由显式详情请求提供。

## 验证证据与范围

工作目录 `.tmp/2026-10-31-treasure/` 保存 MCP JSON、游戏日志与 PNG。夹具固定原生单人 offer 为 Anchor，额外分支改为 Calling Bell 或 Astrolabe；仅在 `STS2_AGENT_TEST_MODE=1` 且指定宝箱场景后生效，不注册 LLM 工具。空箱实际持有 Silver Crucible，使用原生房间钩子，未替换掉落列表。`extra` 夹具只在隔离测试给原生 RewardsSet 添加固定金币，以验证额外奖励暂停开箱及恢复边界；它不是某个正式遗物组合的验证。`map_pending` 夹具为 Anchor 的获取追加受控异步尾段，在原生 UI 收尾且地图完全就绪后仍保持未完成，最终再增加可见金币，用于检查普通完成的等待边界。

已完成 8 个宝箱图形场景：普通合并领取、先开后拿、跳过、白银熔炉空箱、Calling Bell 嵌套奖励、Astrolabe 未支持选牌、开箱前置额外奖励，以及地图已就绪但遗物效果仍待完成的边界。普通场景另检查地图遮挡、重复领取拒绝及返回后观察稳定性。完整 Python 195 项及 C# 22 项通过；构建 0 警告、0 错误。既有休息处锻造回归 19 次调用/检查、战后奖励回归 29 次调用/检查，以及一次观察续接 10 个战斗原生动作均通过。尚未穷举全部遗物、多人、第三方 Mod 或其他游戏版本；不把编译通过当作行为验证。

## 审阅发现与修复

独立审阅指出地图就绪分支可绕过未完成遗物任务。通过 `map-red2.json` 确定复现：返回 `action_completed/complete=true` 时测试状态仍为 `obtaining=true`、`delayed_done=false`。修复仅约束普通地图完成，保留奖励、选择和人工输入边界优先；不将所有 Pending 统一阻挡在输入页面之前。复合动作同时补充第二次点击前的剩余时间检查，两段等待共享总预算。极慢帧耗尽预算的点击边界只做源码检查，未通过人为挂起游戏帧验证。

宝箱证据报告分别为 `basic-fixed.json`、`open-first.json`、`skip-first.json`、`empty-first.json`、`nested-first.json`、`choice-first.json`、`extra-fixed.json`、`map_pending-fixed.json`，截图位于对应无扩展名目录。修复后的地图场景返回时 `obtaining=false`、`delayed_done=true`，金币也已包含尾段效果。

## 藏宝图补充核对

另核对 `Models.Cards.SpoilsMap` 的 `ModifyGeneratedMapLate/AfterMapGenerated/OnQuestComplete` 与 `OneOffSynchronizer.TryHandleSpoilsMap`。触发依赖当前地图节点的 Quest 标记；会按牌组中实际的 Spoils Map 逐张调用任务完成，默认金币 600，等待 `GainGold`、完成任务及移出牌组。此过程在 `DoNormalRewards` 内被原生等待，因此工具既不提前触发，也不另行补发。

`DoTreasureRoomRewards` 在调用藏宝图逻辑前检查 `Hook.ShouldGenerateTreasure`，返回 false 时直接返回 0，因此本版本白银熔炉首个空箱也跳过藏宝图结算。该组合和藏宝图专项仅核对源码，未列入上面的 8 个图形场景。
