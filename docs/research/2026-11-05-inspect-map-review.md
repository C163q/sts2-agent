> 当前状态：设计讨论中。已核对当前读取、参数、错误处理和相关地图源码，并提供一个依据实现整理的典型 full 示例；尚未新增游戏实测，未修改工具行为。summary 与基础观察的地图内容尚未定稿，本项未核销。暂无阻塞。

总流程见[工具核验清单](2026-11-02-mcp-tool-review.md)，实现证据与未验证范围见[开发核验](2026-11-05-inspect-map-development-notes.md)。

## 优先处理的问题

以下两项已由代码核对确认，尚未修复，也尚未新增游戏内复现。它们独立于 summary 的表达方案。

| 问题 | 影响 | 建议 |
| --- | --- | --- |
| 查看地图被拒绝后，需要再次观察才能操作 | 即使在点击前就确认地图不可打开，原有操作许可仍会丢失 | 沿用已审阅查看工具的规则：明确保证未操作界面的拒绝保留已有许可；已经点击、结果不明或状态变化时重新观察 |
| 错误没有说明具体原因 | MCP 只返回通用的“请求的操作不可用”，无法区分没有对局、页面覆盖、入口禁用或正在过渡等原因 | 核对各分支后返回固定、具体的原因和恢复建议；界面是否提供该工具与实际拒绝使用同一判断入口 |

## 当前能力与典型返回

- `preset` 支持 `default`、`full`、`selectable`；默认 `default`。`summary` 尚不存在。
- 默认返回当前幕可滚动浏览的整个地图。节点和连线读取没有按当前视口裁剪；真正隐藏、透明或未绘制的内容仍不读取。
- `max_steps: N` 沿实际连线裁剪当前点之后最多 N 步的子图，`0` 不裁剪；`selectable` 优先于该参数，只返回当前候选的详情。
- `selectable_nodes` 是原生界面当前允许前往的节点，`next` 是地图连线。飞鞋可能让二者不同，不能互相替代。
- 节点保留类型、可识别的先古之民／Boss 名称、问号已经显示的揭晓类型，以及任务图标标记；不提供未揭晓问号的内容或未来房间详情。
- 打开地图会保留页面；从牌组／牌堆调用时，原生地图按钮会替换卡牌浏览页。成功后可以直接选择当前合法节点。

调用 `inspect_map({"preset":"full"})` 的[完整结构示例](2026-11-05-inspect-map-examples/basic.full.json)依据当前实现整理，采用五个节点表示起点、分叉和汇合。它不是实际对局采样，也不表示真实地图只有五个节点。其他已识别分支及既有实测的适用边界见开发核验。

## summary 的候选方向

建议优先讨论**按分叉和汇合组织路线段**，保留所有节点信息，而不是仅进一步删除字段。地图当前已经没有卡牌正文一类的大段文字，主要篇幅来自坐标、节点 ID 和连线的重复。

| 方案 | 表达与取舍 |
| --- | --- |
| 保留逐节点结构，删去重复坐标 | ID 已包含幕、行和列，可以减少重复，改动和学习成本最低；仍需逐条追踪 `next` 才能理解连续路线 |
| 按分叉和汇合组织路线段，推荐讨论 | 单独列出节点信息，连续路线写成 ID 序列；分叉、汇合处开始下一段。保留每一站及全部连线，不枚举从起点到 Boss 的所有组合。便于沿路阅读，但在分叉密集的地图中不一定比逐节点结构更短 |
| 枚举每条完整路线并给出房间数量 | 容易比较，但公共路段反复出现，组合可能很多；仅有战斗／精英／火堆计数还会丢失顺序，不建议作为基础 summary |

第二种方案的结构草案如下，同样是人为缩小的示例，字段名尚未确认：

```json
{
  "scene": "rewards",
  "screen": {"status": "covered", "view": "map"},
  "act": 1,
  "current_node": "map:1:1:2",
  "visited_path": ["map:1:0:3", "map:1:1:2"],
  "can_travel": true,
  "selectable_nodes": ["map:1:2:1", "map:1:2:3"],
  "nodes": {
    "map:1:0:3": {"type": "ancient", "name": "Neow"},
    "map:1:1:2": {"type": "monster"},
    "map:1:2:1": {"type": "unknown"},
    "map:1:2:3": {"type": "rest_site"},
    "map:1:3:3": {"type": "boss", "name": "Ceremonial Beast"}
  },
  "routes": [
    ["map:1:0:3", "map:1:1:2"],
    ["map:1:1:2", "map:1:2:1", "map:1:3:3"],
    ["map:1:1:2", "map:1:2:3", "map:1:3:3"]
  ]
}
```

`routes` 中相邻 ID 表示原地图连线，完整替代逐节点的 `next`；相同端点表示分叉或汇合。节点 ID 沿用原值，不产生需要另查对照的新编号。名称、已揭晓图标与任务标记仍放在对应节点中。这里没有按当前点删除过去或其他支路，也没有给路线评分。

## 尚待讨论的契约

- summary 是否采用路线段，还是保留逐节点结构；用户另有摘要思路，需合并讨论后定稿。
- `max_steps` 建议继续只控制范围，summary 只控制表达；先裁剪子图，再形成路线段。裁剪边界必须能与原图终点区分。现有 `selectable` 行为保持独立，不与 `summary` 同时取值。
- 飞鞋的无连线候选必须保留真实可选性，不能伪造地图连线。现有深度裁剪允许候选 ID 位于子图外；若调整此规则，需要明确哪些候选详情随返回补齐。
- `get_observation` 的地图展开内容与摘要须一起决定，复用同次地图读取和表达入口；`actions_only`、`top_bar` 仍按各自用途精简。完整图是否进入基础观察、不同预设分别使用哪种地图表示，尚未确认。
- 暂不增加自动推荐路线、隐藏问号预测或自动选路。
