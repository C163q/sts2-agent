# v0.107.1 → v0.111.0 迁移调查

当前状态：调查已完成，迁移尚未实施。已对照两版程序集、资源、本项目调用点与编译结果；本文列出确定需要修改的接入点及后续游戏验证范围。

## 结论与核对范围

玩家可见变化以平衡调整、卡牌和遗物重做、动画及输入体验更新为主。本项目可以保留现有 Mod／MCP 分工和公开工具设计，迁移工作主要落在游戏侧接入、补丁绑定、运行时准备和测试夹具。

当前源码无法直接用于 v0.111.0。原样编译首先报 `NExhaustVfx` 类型缺失；在独立诊断工程中仅用类型别名越过该错误后，又得到 13 处编译错误，其中生产代码 5 处、测试代码 8 处。另有编译器无法检查的伤害方法签名和飞牌重载绑定问题。

| --- | --- | --- |
| 游戏版本／程序集内分支 | `v0.107.1` | `v0.111.0` |
| `release_info.json` 的 commit | `59260271` | `41cef1ea` |
| `sts2.dll` SHA-256 | `d13f3f150b1413b24c3a9c5575cdf5398dc74270877d55dec9a556dd8150bd03` | `2b40d2df538db1ceb5fa48d958c80ab730ada1e07db88a870aff01a661768b9f` |
| .NET 游戏运行时 | `net9.0`／`9.0.7` | 相同 |

| RitsuLib | `0.6.10` | 本机完整目录与留档逐文件相同，已包含 `compat/0.111.0` |

项目核对基线为提交 `40761b2`，Mod `0.86.0`、MCP `0.89.0`、观察结构 `50`。本机安装、旧版归档及证据路径记录在由 Git 忽略的 `docs/local.md`。

取证目录为 `.tmp/2026-11-10-v0.111-investigation/`：`old-source/`、`new-source/` 是 ILSpy 11.2 导出的源码，`old-metadata.json`、`new-metadata.json` 是通过 MetadataLoadContext 读取的程序集类型及成员，`diffs/` 保存源码差异。`audit.json` 保存核对结果、输入哈希和编译错误。游戏资源与反编译产物由 Git 忽略。

目前卡面、稀有度、费用和悬停内容来自原生对象，通常无需逐卡维护适配表。需要调整的是使用旧行为作为前提的夹具、断言和验证记录。

### 动画、输入及流程

- 消耗动画拆成普通版与手牌快速版；变牌、充能球、宝箱和形态特效也有变化。可见性采样及动作等待需要重新做游戏验证。
- 输入系统新增键盘模式区分，确认与结束回合使用独立输入标识；快捷键读取应与当前模式一致。
- 地图增加分享按钮，选路的淡入淡出经由 `RunManager`；奖励页增加离房前清理和 Boss 前进按钮锁定，需验证页面切换后的可用动作及令牌稳定。
- 游戏新增设置与存档迁移。设置迁移链已覆盖 `5 → 6 → 7 → 8`，独立实例准备脚本仍生成 schema 5，应改为按新基线准备并验证首次启动。

## 确定需要迁移的接入点

### 1. 构建、依赖选择与独立实例

[Sts2Agent.csproj](../../src/Sts2Agent/Sts2Agent.csproj) 固定 `RitsuLibReferenceTarget=0.107.1`；[prepare_roundtrip.py](../../scripts/prepare_roundtrip.py) 的依赖检查与安装记录同样固定旧目标。需要统一到 `0.111.0`，同步清单、路径示例及验证后的兼容基线。

本机现有 RitsuLib 0.6.10 已提供 v0.111.0 目标，可以先复用此安装。应在游戏内验证实际加载的兼容运行时，再决定是否调整依赖版本。

现有测试目录的可执行文件是旧版副本，程序集和 PCK 则链接到当前 Steam 安装。新版验证前须重新准备完整运行环境，使可执行文件、资源、程序集和兼容运行时来自同一基线。

### 2. 消耗动画与飞牌补丁

[CardAdditionJournal](../../src/Sts2Agent/Events/CardAdditionJournal.cs) 引用的 `MegaCrit.Sts2.Core.Nodes.Vfx.Cards.NExhaustVfx` 已删除。新版有 `NCardExhaustVfx` 与 `NCardExhaustQuickVfx`；`CardPileCmd` 对从手牌消耗的路径使用快速版，对其他相应路径使用普通版。需要分别核对可见性与生命周期，保留 `card_added.pile` 的可见信息依据。

`NCardFlyVfx.Create` 从一个重载变成两个：

```text
Create(NCard, PileType, bool, string)
Create(NCard, Creature, string)
```

[CardAdditionJournal](../../src/Sts2Agent/Events/CardAdditionJournal.cs) 与 [CardMovementJournal](../../src/Sts2Agent/Events/CardMovementJournal.cs) 都只按方法名查找。随游戏附带的 Harmony 在多重载且无零参重载时会抛出 `AmbiguousMatchException`；两处应显式绑定牌堆飞行签名。

证据：两版类型元数据、新版 `CardPileCmd` 的消耗分支，以及 `harmony-method.cs` 中反编译出的 `AccessTools.Method` 实现。

### 3. 伤害记录入口

[TurnCapture](../../src/Sts2Agent/Events/TurnCapture.cs) 精确绑定的伤害方法已增加末尾参数：

```text
旧：Damage(PlayerChoiceContext, IEnumerable<Creature>, decimal, ValueProp, Creature, CardModel)
新：Damage(PlayerChoiceContext, IEnumerable<Creature>, decimal, ValueProp, Creature, CardModel, CardPlay)
```

旧签名在新版中不存在，当前反射查找返回 null；该初始化早于通信入口启动，会阻止正常启用桥接。迁移时更新准确签名，并验证传递到伤害记录的来源上下文。

`DamageResult` 和 `DamageReceivedEntry` 的反编译源码保持一致。公开 `hp_loss` 等字段继续按原生伤害结果解释，当前未发现调整输出结构的依据。

### 4. 战斗开始与回合生命周期

[CombatJournalScope](../../src/Sts2Agent/Events/CombatJournalScope.cs) 使用的 `StartCombatInternal()` 从公开零参方法变为私有 `StartCombatInternal(CombatTurnState)`，导致现有 `nameof` 编译失败。

新版 `CombatManager` 将回合状态收拢到每场战斗独有的 `CombatTurnState`，用 `CombatId` 区分跨战斗异步工作，并在新战斗启动前等待旧回合循环退出。迁移需要选择并核对初始洗牌、抽牌之前的记录入口，确认 `IsStarting` 与 `Reset` 的交接，验证事件中战斗、遗物触发和结束回合的期间事件。

`CardModel.Play` 新增 `BranchingPlayerChoiceContext`，卡牌效果与战斗结束清理也按战斗身份核对。公共工具继续复用这些原生流程，重点验证选牌暂停、自动出牌、致死伤害和跨战斗交接。

### 5. 药水使用与移除条件

[PotionActions](../../src/Sts2Agent/Actions/PotionActions.cs) 使用的 `Player.CanRemovePotions` 已改为 `CanUseOrRemovePotions`，事件名称同步变化。新属性同时表达使用与移除的原生门控，迁移时与药水槽的 UI 条件共同使用。

对应测试夹具也需更新；覆盖排队使用、弃置、选牌期间、房间切换及同伴目标。

### 6. 快捷键与 UI 帮助

[UiInspection](../../src/Sts2Agent/Observation/UiInspection.cs) 的 `NInputManager.GetShortcutKey` 已删除。新版提供 `GetCurrentHotkey`，按当前输入模式选择 `GetMKbHotkey` 或 `GetKbOnlyHotkey`。

`MegaInput.accept` 拆为 `confirm` 与 `endTurn`；结束回合提示应使用 `endTurn`，其他提示核对原生按钮当前使用的输入标识。现有两处快捷键读取及一处结束回合标识共形成 3 处编译错误。

### 7. 测试夹具与已改变的规则

- `Rng.Counter` 删除，新增 `ToSerializable()`，其中保留 `counter` 和完整随机数状态；种子接口扩展为 `ulong`。Shop、Potion、Play、Event、Divination 夹具需更新随机数状态取证方式。
- `CreatureCmd.LoseBlock` 从 `(Creature, decimal)` 改为 `(PlayerChoiceContext, Creature, decimal, Creature?)`，影响 CompanionChecks 两处调用。
- [TurnFixture](../../src/Sts2Agent/Testing/Fixtures/TurnFixture.cs) 的 `retain_choice` 使用 WellLaidPlansPower，[verify_end_turn](../../tests/game/verifiers/verify_end_turn.py) 仍期望 `choice_required`；新版该能力直接阻止弃手牌，需重新设计此验证场景。
- RNG 保存及种子路径已变，同种子跨版本的具体地图、掉落与顺序应重新采样。保留对合法性、可见性、状态稳定及原生 UI 一致性的断言。

## 建议实施顺序与验证范围

1. 更新构建和测试运行基线，修复确定的编译错误与补丁签名绑定。
2. 在完整新版独立实例验证 Mod 初始化、依赖选择、通信与基础观察，再处理运行期差异。
3. 回归出牌、结束回合、药水、选牌、抽牌／变牌／消耗、血条预示、充能球和永久卡牌事件；覆盖普通与快速动画。
4. 回归地图、奖励、商店、宝箱、先古之民、事件内战斗和局末结算；确认期间事件归属及回执后的状态稳定。
5. 完成后更新 README 兼容基线、构建／加载／测试指南及组件版本。此次调查保持这些现行文档原有的已验证基线。

目前建议先以 v0.111.0 为单一适配目标，旧版环境保留为对照。若后续要求同时支持两版，再据明确差异确定兼容层范围。

## 已执行检查及边界

- 两版 `sts2.dll` 全量反编译完成，均无反编译错误；通过只读元数据读取对照类型、成员与签名。
- 解析两版 PCK 索引，按内部 MD5 对照文件，提取所用英语资源时复核 MD5。解析依据为 [Godot 4.5 的 PCK 读取源码](https://github.com/godotengine/godot/blob/4.5/core/io/file_access_pack.cpp)。
- 当前项目对旧版归档编译成功：0 警告、0 错误，产物输出到调查目录。
- 对新版原样编译及临时类型别名编译均已保存失败日志；两次均通过命令行选择 `RitsuLibReferenceTarget=0.111.0`。诊断工程位于 `.tmp/`，生产代码和工程文件未改动。
- `audit.py` 核对关键输入与调查结论，结果见 `audit.json`。
- 本轮未启动游戏、安装新产物或运行游戏行为测试。当前结论支持确定迁移入口；实际加载、显示与生命周期行为留待适配后的游戏验证。
