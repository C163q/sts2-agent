## 已核实的原生行为

`MerchantRoom.EnterInternal` 提前生成库存并初始化 UI，随后调用房间遗物钩子。关闭商品页时仍然能从模型取到库存，但它不是当前可见信息；接口只在商品页已展开且没有覆盖层时读取。

`MerchantInventory.CreateForNormalMerchant` 通常生成五张角色牌（两攻击、两技能、一能力）、两张无色牌、三个遗物、三瓶药水和删牌服务。某一角色卡槽设为特价。接口遍历原生 UI 的实际条目，不硬编码数量；正文使用原生 `PileType.None` 上下文，摘要复用已有牌组序列化逻辑。

`NMerchantSlot.OnSelected` 调用派生 `OnTryPurchase`，后者进入原生购买包装器，维护扣费、发放、历史、补货、钩子、成功/失败信号和 UI。接口调用该入口，不直接改写游戏状态。药水购入失败不会扣钱；工具不为腾位置自动丢弃药水。

`MerchantEntry.Cost` 仅在真实 `MerchantRoom` 应用价格修正；`OnTryPurchaseWrapper` 也仅在真实商店检查补货钩子。送货员提供折扣和补货；补货替换条目的卡牌/遗物/药水对象，条目本身可以保持相同，因此仅为条目分配 ID 不够。接口按槽位与当前商品对象区分身份，补货使用新 ID。

删牌调用 `OneOffSynchronizer.DoMerchantCardRemoval`，原生偏好允许普通购买取消且要求确认；确认后才扣费、移除卡牌并增加删牌使用次数。删牌包装器不走普通补货；成功时原生 UI 隐藏价格并播放打叉动画，接口保留已用状态、不补出隐藏价格。

`LordsParasol.AfterRoomEntered` 启动独立 `PurchaseEverything` Task，不等待它结束。该任务阻止输入并打开商品页，逐个免费尝试初始卡牌、遗物、药水；每个条目只访问一次，所以送货员新补的商品不会反复购买。最后还会进行不可取消的免费删牌。普通购买包装器的 Task 和阳伞总 Task 均被只读跟踪；选择、奖励或不支持对话优先返回，不能等待暂停中的父任务。

假商人事件用相同商品 UI，随机选六个假遗物，价格以 50 为基准，并沿用遗物价格的原生随机浮动。真实商店专属折扣和补货不会触发，阳伞的房间钩子也不处理这个事件。观察不新增“假商人”标签，不把内部事件类型当作画面公开信息。

`FoulPotion.GetFoulPotionMerchantTarget` 只在商品页关闭时给出目标。普通商人收到后，`OnUse` 播放反馈并发放药水金币；假商人执行事件逻辑并进入战斗。其 `TargetType` 从战斗外的 `TargetedNoCreature` 变为战斗中的 `AllEnemies`。目标查询与使用继续复用已有工具，跨战斗须等待新战斗可以操作。当前 `usable_here` 根据原生可用性表达提示；`bouncing` 只根据实际 Tween，不凭名称虚构循环动画。

## 后续奖励和战斗切换的回归

原生大锅的 `AfterObtained` 等待五瓶药水奖励。初版额外等待整个商品 `OnSelected`，使奖励页无法正常返回；`cauldron-red.json` 已复现。允许就绪奖励页暂停父交易后，`cauldron-gate-red.json` 又复现丢弃药水被父交易门控拒绝。修正后 `cauldron-first.json` 通过购买、腾槽、领奖和返回商店，期间不等待尚未完成的父任务。

`foul-map-red.json` 复现地图覆盖商店时药水目标查询被拒绝；应保持只读查询，返回不可用和空目标。`foul-run1.json` 已通过修正后的地图查询及正常商人投掷。

`fake-combat-red.json` 复现战斗未开始时误报 `combat_won`。原生 `CombatManager.IsOverOrEnding` 包含 `!IsInProgress`，不能据此报告胜负；现在绑定本次新战斗的 `CombatSetUp/CombatWon/CombatEnded` 事件。`fake-run1.json` 验证假商人购买不受送货员折扣/补货影响，投掷后进入真正可行动战斗。

## 添水与统一药水获取

`Models.Relics.Sozu.ShouldProcurePotion` 对持有者返回 false，不改写已持有药水的使用/丢弃规则。`PotionCmd.TryToProcure` 首先检查 `Hook.ShouldProcurePotion`，拒绝时返回 NotAllowed，不调用 `Player.AddPotionInternal`。

`MerchantPotionEntry.OnTryPurchase` 在获取失败时映射 `FailureForbidden`，立即返回；扣费和普通成功后补货均不会发生。阳伞也使用同一购买包装器，`ignoreCost` 不能绕过药水获取钩子。

`PotionReward.OnSelect` 的规则不同：TooFull 返回 false，其他失败（含 NotAllowed）仍标记奖励已取并返回 true。旧 `claim_reward` 只观察 RewardClaimed 信号，会把没有获取药水的情况同样标为 claimed。本次新增 `not_obtained`，通过本次 `Player.PotionProcured` 事件确认真实获取，不以奖励行消失、ClaimedPotion 非空或最后槽位是否还持有推断。

添水专项图形验证已通过：普通购买返回 failure_forbidden、不扣费且商品保留；阳伞继续领取其他物品并进入免费删牌，三瓶药水仍在原位；大锅奖励点击后空药水栏保持为空、奖励行消耗且返回 not_obtained。无添水的大锅对照仍能丢药腾槽并实际获得奖励药水。

为让 LLM 能查看已持有添水的限制，现有 inspect_relics 也支持暴露的商店，仍逐项检查原生 holder 的可见和可悬停状态；不扩大到被地图覆盖的商店或其他非战斗场景。
