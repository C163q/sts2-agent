## 输入与提交

`play_cards(cards, preset?)`：cards 为非空对象数组，允许一项；每项仅接受整数 card_id 和按目标类型要求提供的整数 target_id，范围与 play_card 相同。preset 为 default/full，省略为 default。拒绝 null、bool、错误类型、未知字段和重复 card_id。

整批提交前验证所有参数、调用开始时已识别的手牌 ID、目标是否必须提供，以及目标 ID 是否属于当前可见对象。错误指出数组项，任何牌都不提交。无需硬编码张数上限，数量由不同的初始手牌约束。

轮到每项时才检查当前可操作牌、资源及目标是否合法。一次无法提交时记录原因并继续后项；不能预测抽牌、资源增长或效果，不能把全部费用相加后预扣。每项调用相同的原生 TryManualPlay，不等待上一张完整结算，也不绕过同步器。每次提交前重查同一局、战斗、回合及真实 UI；选择、终态、覆盖或阶段变化后停止新增提交。已入队部分按原生暂停、取消和执行规则处理，未提交部分不补发。

零提交但请求本身有效时也返回正常批量回执及逐项原因；参数／引用／阶段的整批前置拒绝则走现有错误通道，可提供明确未提交保证。部分提交后不能把单项失败作为整批未提交错误，也不回滚或重试。

## 逐张回执

批量动作在普通精简动作回执外附加 `card_plays`：

```json
{
  "card_plays": {
    "batch_id": "opaque-batch-identifier",
    "results": [
      {"index": 0, "card_id": 7, "target_id": 3, "status": "played", "reason": null},
      {"index": 1, "card_id": 8, "target_id": null, "status": "queued", "reason": null}
    ]
  }
}
```

batch_id 是独立生成的控制关联标识，不复用观察令牌或文件请求 ID；index 从 0 起对应原数组。所有项都保留，原顺序不变。default 省略普通 null，full 保留。不得添加正文、位置、隐藏数值或推断原因。

| status | 证据与含义 |
| --- | --- |
| not_submitted | 尚未提交，或按项校验／原生 TryManualPlay 拒绝；有公开 reason。 |
| queued | 已捕获对应原生入队，尚未执行。 |
| resolving | 原生已开始处理，可能正在等待选择；不表示效果完整发生。 |
| played | 已可见地进入真实手动出牌流程，原生动作已结束；不保证正文每个效果都发生。 |
| not_played | 原生动作已取消或结束，但未进入真实出牌流程；取消原因不根据事后状态猜测。 |
| unknown | 异常、未能看到实际出牌或对局替换导致结果无法确认。 |

原生 Finished 与取消通知分别记录；已有 CardPlaying 生命周期事件用于真实出牌证据，自动出牌和其他卡牌的事件不能冒充当前请求项。多次触发同一手动牌不增加输入项。UI 隐藏期间的实际效果不补记为已见；私有证据只用于防止误报 not_played。

选择边界立即返回，transition.complete 仍表示到达本次交互边界，不表示整批结束。未完成的已入队项目保持只读追踪；后续有 transition 的成功动作回执附加同一 batch_id 的更新列表，包含原输入所有项。原生终态项目已报告后释放订阅；新局／外部战斗替换清理旧追踪，不把旧 ID 用于新场景。完整观察和普通详情不回放此列表。

超时不撤销原生队列；仍可在同一场战斗的后续动作回执更新尚未完成的批次。新的合法批量调用可以替换已经终结的旧批次；不提供持久任务查询、跨进程恢复或未收到回执的补发保证。异常或取消调用不发布新的动作许可。

## 现有问题与小范围重构

- PLAY-01：共用阶段合法性和拒绝原因，区分无对局／战斗、选牌、地图、卡牌浏览、过渡、拖牌、目标选择和未就绪阶段。目标查询与单张调用复用同一入口，批量后续提交明确允许已有队列。
- PLAY-02：使用已核对的原生拒绝气泡格式化逻辑与英语读取作用域，保留 UI 公开的阻止来源标题。未支持或无法安全格式化时使用通用原因，不输出内部类名。对 RitsuLib 的自定义资源 flag 不猜测原版机制。
- PLAY-03：参数和拒绝说明直接说明当前对象 ID；仅在目标要求不清楚时建议 inspect_targets，不引入额外读取门控。
- 参数解析、玩法校验／诊断、原生提交追踪、批量编排分离；复用现有 ActionObservation、CombatJournalScope、缓冲与输出管线，不编写结算器。
- `card_plays` 的结构及合法状态必须在默认过滤前校验，原生未知字段过滤；play_cards 的返回须与输入逐项对应，不能以缺失／错配批次刷新动作许可。
