# 问号房、事件选项与专属交互调研

## 结论与本次范围

本次完成目标版本的源码调研与接口设计建议，尚未实现通用事件工具，也未更新或安装 Mod。当前实现基线为提交 `4b088c5`、Mod `0.25.0`、MCP `0.21.0`、观察结构 `10`；现有能力以[接口说明](../development/mcp.md)为准。本文后面的新工具、JSON 和分期均为待实现方案。

问号是地图节点类型，不是独立的房间交互。进入后应按实际房间使用既有战斗、商店或宝箱接口；只有真实事件房需要新增适配。推荐使用共享的原生事件选项接口，加少量专属界面适配，不为每个事件编写效果规则。

目标版本注册了57个普通事件模型：54个默认布局、2个战斗背景布局、1个专属布局。这个数字包含条件出现、任务强制替换的事件，不等于57个事件都能随机遇到，也不代表已经实测全部事件。占卜 `CrystalSphere` 本身是默认布局，选项之后才打开小游戏覆盖页。

建议分三步实施：通用事件与场景衔接、占卜小游戏、事件确认弹窗。第一步必须覆盖往返战斗、死亡警告、动态文本和结算边界，不能仅增加“点击选项”。每一步分别完成隔离图形验证和提交；未支持的界面明确停在人工输入边界，不自动代选。

## 问号房与佛珠手链

`RunManager` 对 `MapPointType.Unknown` 调用 `UnknownMapPointOdds.Roll`，结果才决定真实房间类型。普通战斗、商店、宝箱无需新增“问号版”工具；读取与动作不能依据地图上的问号图标推断房内内容。

佛珠手链从原生候选集合中移除 `RoomType.Monster`，不会阻止玩家在事件里主动选择战斗。它也没有移除 `RoomType.Elite`；精英在该版本默认权重为负，特殊挑战改变候选/权重时须另行核对。首局的新手问号分支在调用候选 hook 前提前返回，也不适合概括成所有情况下“绝对不会战斗”。这些机制由游戏执行，MCP 不自行重新抽取房间。

灯火钥匙是任务卡 `Models.Cards.LanternKey`，不是同名遗物。它在第三幕将问号候选限定为事件，并通过 `ModifyNextEvent` 强制替换成 `WarHistorianRepy`。后者的 `IsAllowed` 固定返回 `false`，仅检查随机出现条件会错误地漏掉这条任务路线。

## 事件共用流程

### 观察与点击

默认布局和战斗背景布局都使用 `NEventLayout.OptionButtons` 与 `NEventOptionButton`。按钮通过 `NEventRoom.OptionButtonClicked` 进入原生 `EventSynchronizer`，保留正常选项历史和效果；不应直接调用私有回调、发金币、给遗物或修改卡牌。

`NEventRoom.SetOptions` 在事件完成后生成一个绑定自身 `Proceed` 的原生选项。普通选项也可能叫“离开”“继续”“战斗”，必须点击玩家实际看到的一页，不能按名字自动略过。选项对象会随页面更换，工具 ID 应绑定当前事件实例及真实选项身份，不能将每页数组下标当作跨页稳定 ID。

`NEventLayout` 用透明度及 `visible_ratio` 展示正文，按钮也有独立入场动画。基础观察只返回当前实际显示的信息；动作完成应等到正文展示及按钮可操作。首次进入或页面切换途中，不应直接把模型内完整正文当成已经出现在画面上的文字。观察读取不得为了获得结果而调用 `GenerateInitialOptions`、`CalculateVars`、随机属性或未来页面生成逻辑。

### 红框与可操作性

原生 `EventOption` 支持 `ThatDoesDamage`、`ThatDecreasesMaxHp`、`ThatWillKillPlayerIf`。`NEventOptionButton` 在其判定成立时显示 `RedFlash`，悬停时脉冲闪烁。基础观察建议增加 `lethal_warning`，表达这个原生可见警告，而不是模拟所有伤害与复活机制，或承诺“点击必死”。锁定选项的红色标题与致死红框是不同信息。

单人原生流程允许点击带致死警告的选项；多人有阻止事件死亡的专门处理。第一步保持项目当前实际单人范围：提示警告并按原生规则执行，不自动把危险选项改为禁用，也不替 LLM 选择其他选项。事件外死亡需要可辨识的终止结果，不能等下一回合或超时。

### `IsProceed` 不能直接映射为打开地图

`Trial.Reject` 生成的 `DOUBLE_DOWN` 选项设置了 `isProceed:true`、`disableOnChosen:false`，回调却是打开放弃本局确认框。这个标记同时影响同步路径，并不等于地图旅行。

设计上只有识别到事件完成后由 `NEventRoom` 生成的原生前进按钮，才向 `proceed()` 映射；至少同时核对当前事件已完成、`TextKey == "PROCEED"` 及实际按钮身份。`Trial` 的特殊选项仍由通用事件选项工具点击。取消弹窗后它可以再次点击，不能沿用先古选项中“一旦 `WasChosen` 就拒绝”的通用假设；应尊重原生 `DisableOnChosen` 及实际按钮状态。

## 场景衔接与结算边界

| 原生流程 | 接口需要做到的事 |
| --- | --- |
| 选项直接改生命、金币、遗物或牌组 | 等原生任务、可见计数和预览完成，再返回新事件页 |
| 选项打开移除、升级、变牌、附魔或简单网格 | 复用[选牌工具](../development/card-selection.md)，在需要输入时立即返回 |
| 选项打开一个或多个奖励页 | 复用[奖励工具](../development/rewards.md)，不替玩家领取、跳过或固定领取顺序 |
| 选项进入战斗 | 识别新战斗实例；等待首个真实可行动或选牌边界，保留战斗中途直接结束的可能 |
| 战斗奖励后的前进 | 原生可能返回事件，也可能打开地图；返回真实结果，不假定一定开地图 |
| 返回事件后的奖励、遗物领取或预览 | 原生返回任务继续执行；不能在事件前进按钮先出现时提前报告结算完成 |
| 事件造成死亡 | 返回终止状态；不再开放事件动作，不把它报告为加载或等待玩家回合 |
| 未接通的专属覆盖页或弹窗 | 及时返回 `manual_input_required`，报告已识别的页面，不穿透点击底下的事件 |

`DenseVegetation.Rest` 先治疗并显示含 `FIGHT` 的新一页，下一次点击才进入战斗；`TrudgeOn` 才是掉血并得金币的另一条路线。`TheLanternKey.KeepTheKey` 同样先显示战斗页，再由 `Fight` 创建战斗与任务卡奖励。这些战斗设置 `shouldResumeAfterCombat:false`。

`BattlewornDummy` 设置 `shouldResumeAfterCombat:true`，战斗结束后由奖励页前进返回事件。`Resume` 根据结果可能给药水奖励、随机升级两张牌或领取遗物；时间耗尽也有不同结果页。因此战斗场景的前进必须保留原生 `ProceedFromTerminalRewardsScreen` 路径，不能统一替换为 `OpenMap`。

现有 `NonCombatBoundary` 仅认识奖励、休息处、宝箱、商店及先古之民，尚未覆盖普通事件。现有 `AncientInspection.Busy` 读取 `_pendingOptionTasks`，但 `EventSynchronizer.ResumeEvents` 使用 `TaskHelper.RunSafely(event.Resume(...))`，没有把返回任务放入这个列表。简单扩大现有场景判断仍可能提前完成。

建议增加原生事件任务跟踪，分别观察选项、返回事件及必要的初始化任务；对返回任务需覆盖实际 override，不能只拦截基类空实现。跟踪用于判定任务状态，不替换执行顺序，不在游戏线程同步等待。子选牌、子奖励与专属界面优先作为输入边界；它们会暂停父任务，不能要求父任务先完成。可见稳定性继续复用项目已有的卡牌飞行、资源数字及预览判断，不用固定长延时猜结算时长。

事件结算期间也应接入药水动作门控，防止并发改变当前候选或代价；暂停在已就绪的子奖励页时，仍应允许原生支持的丢弃药水以腾出槽位。`RanwidTheElder`、`StoneOfAllTime`、`TheFutureOfPotions` 会临时设置 `CanRemovePotions:false`，必须尊重游戏自身的限制与恢复时机。

事件动作在进入战斗前订阅原生战斗生命周期；不能用“还是同一个事件模型”作为持续等待条件，因为 `EnterCombatWithoutExitingEvent` 会清空原事件 `Node` 并切换房间。第一次自动阶段可能先选牌、自动出牌、死亡或胜利，不保证一定返回普通 `player_ready`。终止、超时、覆盖及许可失效语义需要与 Python 端一并实现。

## 专属交互

### 假商人

`FakeMerchant` 是这57个模型中唯一的 `EventLayoutType.Custom`，使用 `NFakeMerchant`，没有普通事件选项。已经接通的[商店工具](../development/shop.md)继续负责打开、关闭、查看、购买和使用污浊药水；观察维持商店身份，不额外公开其隐藏身份。

`FoulPotionThrown` 会进入战斗，额外奖励包含地毯以及符合原生条件的未售遗物，设置不返回父事件。本次不另加“假商人事件工具”，也不把未领取遗物提前当成已获得物品。已有商店路径仍需纳入事件功能回归。

`TeaMaster`、`WelcomeToWongos` 虽然收金币，也都是普通选项页面，不能因为含购买逻辑而强行识别成商店库存页。

### 占卜 `CrystalSphere`

初始两条选项分别扣除页面显示的金币，或获得 `Debt`；随后打开 `NCrystalSphereScreen`。小游戏初始剩余次数分别为3或6，网格11×11，默认大范围工具。小范围揭一格，大范围揭以指定格为中心、经过边界裁剪的3×3区域；一次点击消耗一次次数。已经揭开的格子原生不可再点击。

操作应点击真实 `NDivinationButton` 和 `NCrystalSphereCell`；不得直接调用 `CellClicked`、修改格子或奖励。推荐第二步新增：

- `set_divination_tool({"tool":"small"})`，或 `"big"`：显式切换原生工具，使变化呈现在 UI 上。
- `divine({"x":5,"y":5})`：点击观察中当前可选格子，坐标为0起始，左上角 `(0,0)`。
- 详情读取初步复用 `inspect_event()`；结束后实际启用的前进按钮继续复用 `proceed()`。

基础观察应包含剩余次数、选中工具、按钮、说明和可见网格。`Items`、`cells[x,y].Item`、完整物品矩形等底层数据在雾下已经存在，不能直接序列化。局部揭开时玩家能看到图标碎片，因此只返回“已揭开/未揭开”也会少给玩家可见信息；同样不能由一角碎片直接补出整个被遮挡物品的身份、边界或价值。

第二步应先用真实图形实例验证遮罩：优先为 `get_observation()` 附带当前棋盘区域的图像内容，再提供结构化网格坐标与操作状态；图像来自实际渲染后的棋盘，不能从物品模型重绘。这种自动观察图像与可选的“截图存盘”调试工具职责不同，不能要求后者必须启用才能玩占卜。若客户端图像兼容性或局部可见的文本表达尚未验证，应明确保持小游戏未支持，不能静默漏掉碎片信息或用隐藏模型补齐。最终图像格式、大小及 MCP 输出结构在第二步原型验证后确定，不先承诺完整纯文本支持。

物品全部占用格被揭开时才触发 `RevealItem`。诅咒 `Doubt` 在此时加入牌组；其他已揭示物品在次数耗尽后，由 `CompleteMinigame` 调用原生同步流程结算奖励。药水及遗物等实际随机结果不能由占卜物品图标提前生成或查询。次数为0、小游戏任务结束、奖励页出现和前进按钮可用不是同一时刻；必须区分自动结算、等待奖励输入和最终前进。

### `Trial` 的确认框

拒绝后继续拒绝会打开原生 `NAbandonRunConfirmPopup`；确认调用 `RunManager.Abandon`，取消只关闭弹窗。不能自动确认，也不应将它混入只操作卡牌的 `selection_option`。

第三步建议新增 `respond_to_confirmation({"option":"cancel"})`，另一个值为 `"confirm"`；只在由当前事件打开、已经识别且可见的这个确认框上启用。基础观察提供原生标题、正文及两个按钮；底层事件内容按覆盖规则隐藏。取消后返回事件并允许再次点击原选项。未知弹窗继续明确报告未支持，不顺带开放设置、删存档等无关确认操作。

## 英语文本与信息边界

项目当前使用独立英语资源格式化文本，不切换游戏语言。事件比先古遗物包含更多进入时已格式化的 `StringVar` 与缓存 `HoverTip`，只套用现有 `EnglishCardText.Read` 仍可能混入中文：

- `RelicTrader` 缓存三组当前交易遗物名；不得再次调用会抽取遗物的懒加载属性。
- `TheFutureOfPotions` 将药水、稀有度、牌型格式化进每个选项。多个选项共享同一文本键，仅按文本键匹配无法区分当前药水。
- `TeaMaster` 缓存整段遗物效果；`SelfHelpBook`、`SapphireSeed`、`Symbiote`、`WoodCarvings` 等缓存附魔名称。
- `EndlessConveyor` 缓存当前及上一个菜名；读取不能滚动下一道菜。
- `Trial` 将当前故事或结果的原语言原文嵌入另一条模板，不能只翻译外层。
- `SlipperyBridge` 的待移除卡牌、`DollRoom` 的当前遗物、`TinkerTime` 的卡牌效果预览已经通过当前选项及悬停公开，允许详情查看；尚未出现的后页和随机选择不公开。

第一步需要一个只读的事件文本适配层：根据当前真实选项、已公开引用和对应资源生成分离的英语变量/悬停说明，保留真实数值、卡牌升级后名称和动态效果；不改写游戏对象、原变量或缓存，也不重新执行选项生成。测试应核对重复详情读取不推进页面、不修改牌组、不消耗 RNG，并在中文游戏中检查混合语言。

## 推荐工具与观察草案

可选方案有三种：为每个事件添加工具会重复实现游戏规则；将所有场景与先古工具一次统一迁移会扩大兼容与回归范围；推荐保留现有先古、商店、奖励及选牌工具，新增通用事件入口，只抽取本次需要共用的按钮和任务跟踪逻辑。

第一步建议新增两个工具：

| 工具 | 待实现行为 |
| --- | --- |
| `inspect_event()` | 当前普通事件页面正文、选项及原生悬停详情；不推进、重新生成或代选 |
| `choose_event_option({"option_id":0})` | 点击当前已观察且启用的真实选项，返回下一可行动边界 |
| 复用 `proceed()` | 点击已识别的事件结束前进按钮；战斗奖励路径仍可能返回父事件 |

既有 `choose_ancient_option` 保留先古语义；不让它顺便点击普通事件，也不要求 LLM 把普通事件误当成遗物三选一。`advance_dialogue` 继续处理现有先古对话；普通事件的“继续”通常就是选项，无需第三个推进工具。

以下仅为结构示意，文字为示意内容，不是实际事件或现有接口返回：

```json
{
  "scene": "event",
  "event": {
    "status": "visible",
    "name": "Example Event",
    "description": "The currently displayed page text.",
    "options": [
      {
        "id": 0,
        "title": "Example choice",
        "description": "Lose 5 HP.",
        "enabled": true,
        "lethal_warning": true
      }
    ],
    "proceed": null
  },
  "available_actions": ["choose_event_option"]
}
```

`inspect_event` 在每项增加 `hover_tips`，基础观察不附送悬停内容。覆盖时 `status:"covered"`，其余内容为 `null`；嵌套卡牌候选仍放在既有 `selection`，奖励仍放在 `rewards`。假商人维持 `shop`，不追加泄露身份的事件对象。

动作沿用当前观察许可与快照校验。完整动作结果在下一边界明确可操作时可以继续链式调用；普通只读详情不新建许可，视图切换仍按现有规则清除许可。每页稳定 ID、原生按钮启用、线程及生命周期验证在 Mod 端完成；Python 端同步增加严格参数、递归过滤、新场景与停止原因校验，避免 Mod 已识别而 MCP 仍丢掉新字段。事件外死亡建议使用明确的 `run_lost` 停止原因；这是新契约候选，不能只改 C# 输出而遗漏 Python 许可与终止处理。

## 分期验收与未验证事项

第一步的代表性隔离图形场景应包括：简单即时选项；多页循环与旧 ID 拒绝；金币不足锁定；致死红框及单人实际死亡；卡牌移除、多选、升级、变牌、附魔；嵌套奖励与满药水栏、添水；`DenseVegetation`、`TheLanternKey`、`PunchOff` 的战斗入口；`BattlewornDummy` 战后返回各奖励分支；`LanternKey` 强制任务入口；长时间逐张预览的 `Reflections`；`TinkerTime` 动态卡牌；至少覆盖上述缓存文本种类的中文界面英语输出。占卜和确认框在本步明确返回未支持，且不得超时或穿透操作。

第二步需验证3/6次数、大小工具显式切换、边缘裁剪、已揭格拒绝、局部图标与雾下信息边界、诅咒即时加入、最终奖励及其嵌套选牌、原生前进。应比较多个隐藏布局具有相同可见棋盘时的观察，确保没有隐蔽模型或未来随机结果进入 JSON；同时逐张截图检查视觉可见信息未被遗漏。

第三步需验证 `Trial` 点击红框特殊选项、确认框覆盖、取消后重试、明确确认后本局结束，以及未知弹窗不会开放按钮。现有先古、商店、宝箱、休息处、奖励、出牌及选牌动作都需做相关回归。

`ByrdonisEgg.TryModifyRestSiteOptions` 会新增 `HATCH`；当前 `RestSiteInspection.Supported` 已包含这个原生选项 ID。这里只确认代码路径存在，事件获蛋到休息处孵化的连贯行为仍需图形回归，不能凭白名单就标为本次已验证。
