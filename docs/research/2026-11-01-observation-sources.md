# MCP 结构化读取与动作续接

## 基线与问题

核对日期为 2026-11-01，代码基线为 `7066d3a`，游戏为 Linux `v0.107.1`，RitsuLib 为 `0.6.10`。本次仅将 MCP 从 `0.29.0` 更新至 `0.29.1`；Mod 保持 `0.34.1`，文件协议与观察 schema `16` 不变。

反馈来自本地 `playtest-2026-11-01-v5/summary-notes.txt` 及同目录 `interaction-evidence.json`。原始调用顺序为 `proceed → get_observation → inspect_map → travel_to_node`，最后一步返回 `observation_required`。地图已经打开且能旅行；Python `GameTools._change_view` 却在重复查看时也无条件清除令牌，丢弃成功结果提供的新令牌。普通详情同样只保留与旧令牌相等的令牌，不能独立支持下一动作。

这些行为与旧文档一致，但造成多余读取。本次同步修改实现、提示词及持续维护文档，取消对特定观察工具的专属依赖；summary 字段建议不在本次范围内。现行完整契约见 [MCP 调用语义](../development/mcp.md#调用和错误语义)。

## 实现

- 成功的基础观察、专项详情和视图操作都使用该结果的新状态令牌，允许首次直接查看相关详情，也允许详情刷新已变化的状态。
- 地图详情后可直接旅行；关闭牌组或牌堆后可直接操作当前界面；返回选择视图后可直接提交已读取的候选。覆盖页仍需显式关闭。
- 截图不提供结构化游戏状态，只在采样令牌与已有令牌相同时保留旧许可。失败、坏响应、超时和取消不发布新令牌；不自动补发或重试未知结果的动作。
- 动作原有的完整结果续接条件、排队请求检查、控制锁及 Mod 在游戏线程执行前的状态与合法性复核保持有效。新读取不允许穿透页面、选择隐藏候选或旅行至非法节点。

没有新增模型参数、权限字段或自动观察调用。错误中的 `recovery: get_observation` 保留为通用恢复入口，错误消息和说明明确相关详情也可提供当前状态。42 个默认工具及可选截图工具的 schema、注解和顺序与基线相同。
