## 重构约束与方案

采用保留接口的分批重构：维持 12 个 MCP 工具、参数、文件操作、启动命令、SDK 依赖和 Mod；新增递归输出投影，把 MCP 会话与工具目录从启动模块分开。合法游戏样本的解析结果保持一致，错误响应更严格，JSON 文本仅改变无语义空白。

另一个可选方案是同时迁移到正式 Python 包、`src/`、`tests/` 和独立 C# 测试项目。它有利于后续发布，但会同时改变配置路径、脚本导入和验证流程；当前收益不足以覆盖额外回归范围。本次不采用。仅移动文件而不处理边界问题也不能满足审阅目标。

基础观察保留可见信息边界；不自动附送卡牌正文，不读取抽取顺序，不合并会改变查看行为的工具。游戏线程与后台传输、真实 UI 操作与纯只读详情、基础观察与详情继续分离。

## MCP JSON 与官方实践

这里必须区分三层：

1. **协议传输**：stdio 每条 JSON-RPC 消息以换行分隔，消息内部不得有实际换行；JSON 字符串中的 `\n` 是转义字符，不会破坏分帧。HTTP 的分帧规则不同。[MCP 2025-11-25 transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
2. **工具文本**：`content[].text` 是字符串，可以包含紧凑或缩进 JSON；`structuredContent` 是对象，本身没有“缩进”属性。客户端决定如何转换成模型上下文，界面显示不能证明实际模型输入格式。[MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
3. **人类查看**：终端输出、样本文件和调试报告保留两空格缩进，便于核对。JSON 结构字符附近的空白没有数据语义，不可删除字符串正文中的换行或空格。[RFC 8259 §2](https://www.rfc-editor.org/rfc/rfc8259#section-2)

原 MCP 文本使用 `json.dumps(..., ensure_ascii=False)`，没有缩进或排版换行，但分隔符后保留空格；CLI 使用 `indent=2`。本次选择 MCP 文本紧凑序列化 `separators=(",", ":")`，CLI 与证据文件继续格式化。它减少文本大小；没有实测具体 tokenizer 时，不将字节降幅说成 token 降幅，也不声称模型正确率必然提高。

原始正式样本的 UTF-8 大小比较（不含文件末尾换行，不含 MCP 外层）：

| 样本 | 两空格缩进 | 原 MCP 格式 | 紧凑格式 |
| --- | ---: | ---: | ---: |
| 地图 | 9743 | 6009 | 5333 |
| 完整牌组 | 4078 | 3044 | 2799 |
| 摘要牌组 | 2513 | 1861 | 1682 |
| 手牌详情 | 2385 | 1791 | 1657 |
| 战斗对象 | 1262 | 888 | 836 |

MCP 对返回结构化结果的工具建议同时返回 JSON 文本以保持兼容；本次保留两种表示。客户端是否把两份都送给模型，需要在目标客户端核对，不能仅凭服务返回两份就认定 token 翻倍。[MCP structured content](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#structured-content)

工具设计应优先消除重复和无关信息，保留明确的参数、副作用和恢复方式，用真实任务评估成功率、调用次数、延迟及 token；没有适用于所有模型与任务的唯一最佳输出格式。本项目的按需详情、共享解释和摘要/完整档位已符合这一方向。当前数据量与“查看整个原生列表”的契约不支持无条件引入截断或分页。[Anthropic：Writing effective tools for agents](https://www.anthropic.com/research/writing-tools-for-agents)
