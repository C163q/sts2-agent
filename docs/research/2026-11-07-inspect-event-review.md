## 优先问题

| 问题 | 影响与建议 | 状态 |
| --- | --- | --- |
| 普通事件与占卜拒绝读取时只有通用错误 | 中：无事件、页面被覆盖、占卜正在揭开等原因均变成“操作不可用”。应公开具体原因，并让 available_actions 与详情使用同一读取条件 | 源码确认，待修复；已有读取拒绝恢复许可的共用机制，无需重复增加 |
| 详情接受互相矛盾的页面与主体 | 中：受控响应中，地图覆盖仍带可见事件、牌组覆盖仍带可见棋盘，当前校验均接受。应在授予许可前核对主体和 scene/screen 一致 | 两个受控输入确认，待修复；不代表原生游戏实际生成了这些响应 |
| 纯文字缺少已揭开碎片线索 | 中：JSON 仅能区分覆盖／揭开，瓶塞、瓶底和牌框部位仍依赖 PNG。增加经过可见性核验的文字表示 | 已确认需求，表达方案讨论中 |

另有两项需要在实施前核验：事件选项仍按视口坐标过滤；悬停帮助直接使用“可点击”条件。两者需要区分静态展示、可悬停与可点击，但尚未新增游戏用例证明正常页面实际漏读或多读，不能据此宣称已有实测故障。

## 当前用途、参数与典型返回

当前只接受 preset:default/full，无操作参数。普通事件返回当前事件及选项的悬停说明；占卜返回棋盘、次数、工具、教学、对白和 PNG。先古之民、建筑师、试炼确认框、事件引出的选牌及奖励分别由各自工具处理。

普通事件即使尚未能点击，也允许读取已经展示的内容；占卜详情则要求揭开、资源及奖励等流程就绪。占卜在结算中仍可由 get_observation 观察；详情是否放宽为同一读取边界，需要与动作可用条件分开核验。

[两份完整 full JSON](2026-11-07-inspect-event-examples/README.md)将历史游戏主体经当前读取器重放，展示当前返回结构；不是当前版本新跑的 GUI 样本。占卜现状有独立 PNG 内容块，JSON 仍只有 covered_rows。default 使用共用空值过滤。

## 实际图案与尺寸

以下尺寸为横向格数 × 纵向格数。目标版本生成器放置时平移物品，不旋转。

| 外观类别 | 尺寸 | 当前生成情况 |
| --- | --- | --- |
| 单枚金币／金币堆 | 1×1／2×1 | 均会出现 |
| 普通药水／稀有药水 | 1×3／2×2 | 均会出现 |
| 普通、罕见、稀有卡牌奖励 | 2×2 | 三类均会出现 |
| 诅咒图案 | 2×2 | 会出现 |
| 遗物箱图案 | 4×4 | 会出现 |

“卡牌奖励”是奖励类别图标，具体候选牌尚未生成；药水和遗物同样不能提前给出最终随机物品。

卡牌奖励在游戏中由牌框、阴影与横幅组合绘制。三种稀有度共用牌框，稀有度由顶部横幅区分。因此，只有下半部可见时，不能按底层卡牌奖励类型标出稀有度。资源中另有罕见药水图，但与普通药水图逐像素相同，当前生成器也未放置罕见药水；这说明模型分类不能直接代替可见外观分类。

## 表达方式比较

| 方案 | 优点 | 代价与风险 |
| --- | --- | --- |
| 每种碎片一个单字符 | 棋盘紧凑，接近字符图 | 字符与部位的对应需要反复查表；同一字符复用会丢方向，强行唯一又可能泄露无法区分的身份 |
| 多字符碎片代码与完整图案对照 | 能用 potion.top、card.lower_left 等可读名称，仍能排列成棋盘 | 每格文本较长；对照表须按真实可辨别部位分组，不能机械按奖励类型及内部格序编号 |
| 覆盖棋盘加可见碎片列表 | 保留现有坐标操作；部位名称直接表达方向，避免每格填充长名称 | 需要静态外观字典；不确定部位须明确保留，不能为了方便而补全 |

采用第三种，并增加棋盘中的碎片状态。建议将不再仅表示覆盖的 covered_rows 改名为 cell_rows，get_observation 与 inspect_event 共用：

| 字符 | 含义 |
| --- | --- |
| `#` | 仍被覆盖 |
| `.` | 已揭开且没有可见图案，或原有边缘空白 |
| `s` | 有可见图案，所属整体尚未确认全部揭开 |
| `S` | 可见图案所属整体已全部揭开 |

同一图案完整揭开后，其可见图案格由 s 改为 S；透明留白仍为 `.`，不按内部占用矩形填满。无法识别但确有图案的格子使用 s，并在碎片记录中保留 unrecognized。完整揭开不等于已经领取奖励。

原生物品完整揭开会播放闪光及缩放，界面还会播放对应对白；完成状态并非凭内部奖励列表推断。实现仍需核对图案整体与可见格子的对应，不能因知道雾下物品位置而补出完整边界。原生动画结束后，完整图案本身仍应作为判断依据。

具体部位仍由 visible_fragments 描述，s/S 不承担图案分类。以下仅演示候选字段，坐标与部位不是实际游玩输出：

```json
{
  "visible_fragments": [
    {"x": 5, "y": 5, "appearance": "potion.base"},
    {"x": 7, "y": 6, "appearance": "card.lower_left"},
    {"x": 3, "y": 4, "appearance": "unrecognized"}
  ]
}
```

`potion.base` 表示可辨别的瓶底；结合已核实的固定图案，模型可以推断应继续向上揭开。`card.lower_left` 只描述牌框部位，不带下半部无法证明的稀有度。如果图案不足以判断上下或左右，应使用更宽泛的部位名称；仍无法识别时返回 unrecognized，不能强行选出真实部位。

已揭开但没有可见图案的格子由 cell_rows 中的 `.` 表达；有图案但识别失败的格子必须有明确记录。相邻碎片是否属于同一件物品，也应由可见线索判断，不能直接附上内部物品 ID 将它们分组。

## 已确认的摘要与筛选规则

以下规则已确认，尚未实现。get_observation 的 full/default/summary 均采用 inspect_event.summary 的事件与占卜主体省略策略；actions_only/top_bar 继续使用各自既有范围。

| 场景 | summary 保留 | summary 省略 |
| --- | --- | --- |
| 普通事件 | 事件名称；选项 ID、标题、效果 description、enabled；值为 true 的 lethal_warning；proceed 及上下文 | 页面叙事 description、全部 hover_tips、false 致死警告 |
| 占卜 | 阶段、次数、当前工具与工具按钮、完整文字棋盘、可见碎片、当前完整对白、proceed 及坐标图例 | 固定教学 instructions |

| 调用 | 事件与占卜主体 |
| --- | --- |
| inspect_event.full/default | 完整已显示叙事、可悬停选项说明及占卜教学；default 另执行共用空值过滤 |
| inspect_event.summary | 使用上表的省略规则 |
| get_observation.full/default/summary | 均使用上表的省略规则；其他场景与顶栏继续遵循各自预设 |

普通事件与占卜各有共用摘要入口，基础观察和事件详情从同一份可见数据投影。get_observation 的 full 不自动展开专门查看内容。所有上述预设完整保留棋盘与已揭开线索，摘要不减少碎片或将未知当成空白；图片的附带规则单独决定。

暂不增加筛选参数：普通事件的选项列表较短，summary 已能去除叙事与悬停正文；占卜的 11×11 棋盘需要保留邻近格子和完整覆盖状态以安排揭开。当前没有必须新增选项 ID 或坐标范围筛选的需求。

## 建议实现边界与下一步

先做一个有限的识别验证，再确定最终字段和是否以文字替代默认 PNG。文字观察应由当前已揭开区域的实际图案与静态外观字典产生；不能直接把内部物品类型、位置和格内偏移改写成“看到的部位”。

验证重点是单格瓶塞／瓶底、稀有药水四个部位、不同稀有度卡牌的相同下半部、遗物箱局部、透明留白、相邻物品与不同窗口缩放。遮住的内容发生变化而可见图像相同时，文字结果应相同。若部分碎片无法可靠区分，应合并为同一种外观或保留未知，并说明纯文字仍缺少哪些线索。

小范围重构建议限于两个入口：普通事件的页面检查／静态选项／悬停判断，以及占卜的共用可见棋盘读取。get_observation 与 inspect_event 从同一份棋盘结果投影，图片作为独立媒体处理。

尚未决定：最终碎片词表、图案对照的提供方式、PNG 默认与可选规则。摘要与暂不筛选的已确认规则见上节。没有授权新增其他 TODO 项，也没有修改现行工具行为。
