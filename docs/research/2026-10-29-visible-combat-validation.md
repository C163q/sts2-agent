# 战斗可见观察验证

基线：2026-10-29，本地 Linux 游戏 `v0.107.1`，提交 `59260271`，.NET SDK `9.0.122`。目标程序集仍为 `data_sts2_linuxbsd_x86_64/sts2.dll` 与 `GodotSharp.dll`。字段依据见 [来源调研](2026-10-29-observation-data-sources.md)，现行接口见 [战斗观察 JSON](../development/observation.md)。

## 实现与核对

- 新增 `CombatObservation`，从实际战斗节点、标签与图标读取；对象名称从独立英语资源表解析。
- 图形实例中帧后事件成功处理请求，主线程检查未触发异常；中文界面下 JSON 仍返回英语卡名、敌人名和结束回合文字。
- 原生 Vulkan 窗口与同次请求截图用于人工核对。样本为铁甲战士、三只史莱姆：生命 `80/80`、能量 `3/3`、金币 `99`、主牌组 `10`，手牌费用 `2/1/1/1/1`，意图依次为攻击 `3`、状态 `2`、攻击 `4`。
- 样本房间图标实际隐藏，返回空值；首领图标显示 Vantom。版本、种子、Mod 数量从可见标签读取，未从游戏内部随机状态补充。
- 首次战斗教学确实覆盖战斗，观察返回 `covered`；测试场景随后改用独立存档关闭教学，正常观察不会自动关闭教学。
- 生物根节点与卡牌布局容器存在零尺寸情形，运行验证据此改为检查实际显示部件，避免把布局容器当成可见矩形。

原始产物位于不纳入 Git 的 `.tmp/observation-v2.json`、`.tmp/roundtrip/observation.png`、`.tmp/roundtrip/observation.layout.json` 和 `.tmp/roundtrip/observation-checks.json`。截图与布局用于开发核对，不作为 LLM 默认响应。

## 验证范围

13 项游戏内过滤检查已在独立中文图形实例通过：基线手牌、隐藏卡牌、移出屏幕、透明父节点、隐藏的负数费用、实际费用字体颜色、零宽度描边、隐藏生命数字、隐藏意图、隐藏金币、过渡子层遮挡、过渡根 Shader 遮挡及还原后的手牌。

最终构建成功，0 个警告、0 个错误。中文图形实例中完整往返回归通过：回合 `1 → 2`、生命 `80 → 73`，返回与读回令牌一致，非法动作、旧状态及重复请求处理均通过；证据为 `.tmp/roundtrip/observation-roundtrip.json`。Python 安装路径隔离回归通过。已将 Mod `0.2.0` 的 DLL 与清单复制到本机 Steam 安装的 `mods/Sts2Agent/`，安装文件与构建产物的 SHA-256 一致；正常 Steam 对局需重启后再读取，未把独立实例验证当作正式存档行为验证。最终同次读取的 JSON 与截图另存为 `.tmp/visible-combat.json`、`.tmp/visible-combat.png`。未将普通战斗样本的成功扩大为所有 UI 情形已验证：`X` 费用、无限生命、死亡动画、非空药水、多首领、遗物计数、多玩家、其他角色专属资源和任意 Mod 叠加界面仍需对应游戏内样本。当前也未实现逐像素卡牌重叠分析、专门查看卡牌正文的工具或完整动作集。
