# 复用动作返回观察

## 范围与实现

基线为提交 `ed0bcfb`、Mod `0.20.0`、MCP server `0.15.0`；真实游戏验证使用 Linux `v0.107.1`、RitsuLib `0.6.10`，核对日期为 2026-10-30。本次仅修改外部 MCP 层，发布为 `0.16.0`，不改 Mod、文件协议、工具名称或参数，也不实现奖励场景。

原先 `GameTools._action` 消费已有状态令牌后，丢弃响应中的新令牌，尽管结果已经包含完整基本观察。现在先按原流程校验观察及 `transition`、过滤公开动作，再在结果完整并可继续行动时保存新令牌。条件与失效规则统一见[MCP 调用语义](../development/mcp.md#调用和错误语义)，功能指南和工具提示同步更新。

下一动作依然携带 `expected_state`，由 Mod 在游戏线程重新计算快照并核对合法性；MCP 不添加隐式 `get_state`，不自动重试。取消检查发生在保存新许可前。并发调用进入锁前记录已有许可，锁内若许可已失效或被其他请求替换，就拒绝操作，防止已排队请求借用未来返回的观察。只读查看仅保留原有相同令牌，改变页面仍清除许可。

`end_turn` 的非法参数原先由 MCP 分派器直接拒绝，留下旧许可；现进入同一动作锁后校验并清除许可。对外 schema 仍为空参数，正常调用方式不变。

## 验证证据

证据目录为 `.tmp/2026-10-30-action-observations/`。

| 验证 | 结果 |
| --- | --- |
| 新旧行为对照 | 新增 9 个测试方法，旧实现在 20 个子用例失败，`red.log`；覆盖六类动作、三类成功边界、失败/坏响应/取消/无动作、过期令牌和只读查询 |
| 非法参数 | 真实 stdio 测试复现 `end_turn` 失败后仍能行动，`end-turn-arguments-red.log`；修复后要求重新观察 |
| 完整 Python 套件 | 171 项通过，`python-final.log`；原并发动作仅执行一次、视图失效、控制锁及取消测试继续通过 |
| 中文图形 MCP 连续决策 | `pipeline.json` 和三张 PNG；一次观察后连续执行 10 个成功游戏动作，包含使用技能药水、选择候选、武装升级选择与确认、出牌、丢弃/使用药水及结束回合 |
| 状态改变与恢复 | 同一图形测试中，独立文件客户端推进回合后，MCP 返回 `stale_state`，再试为 `observation_required`；打开并关闭牌组页也要求重新观察 |
| 既有真实 MCP 验证 | `basic.json` 通过连续结束回合、读回一致、非法参数清理及外部推进后的过期拒绝 |

连续动作之前仍须完成首次观察；工具在每次响应后由模型重新决策，不提供自动动作队列。这组 10 动作场景将必要的 MCP 观察调用从原规则下的 10 次减少到 1 次，省去 9 次重复读取；动作结果本身仍返回完整状态，不推断通用的 token 或延迟节省比例。

首次在沙箱内运行异步测试挂起，已定位并停止本任务测试进程，随后在允许本地异步通信的环境完成验证。该问题不发生在游戏或 MCP 功能验证中。

## 使用与限制

重连 MCP 以加载 `0.16.0` 脚本和新提示即可，保持已安装 Mod `0.20.0`。正常客户端继续每次调用 `get_observation` 也兼容；是否省去读取由客户端按返回结果决定。正式对局、用户配置、安装的 Mod 和创意工坊 RitsuLib 均未修改。

本次不验证完整自动战斗、真实多人或任意第三方流程，不增加奖励页识别和操作。胜负或不支持选择停止后不自动续接许可；未知结果仍须观察，不自动重发。
