# MCP 工具提示词审阅

核对日期：2026-11-01。代码基线：`ff72bb7`，MCP `0.29.0`、Mod `0.34.0`，项目目标为 Linux 游戏 `v0.107.1` 与 RitsuLib `0.6.10`。审阅覆盖默认 42 个工具及可选截图工具的服务说明、工具描述、参数提示和行为注解。本次只修改英文提示文字及配套文档，不修改游戏调用、参数约束、动作许可或工具注册范围。

## 官方实践与采用方式

- [MCP Tools 规范（2025-11-25）](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)区分功能描述、输入 schema 和行为注解；注解只是提示，不能替代校验。本项目保留现有 schema 及注解，参数取值继续由代码验证。
- [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling#best-practices-for-defining-functions)建议说明用途、参数格式及结果含义，用枚举和结构减少非法调用，并将已知控制信息交由代码处理。本项目继续在服务内部维护观察令牌，把模型必须选择的对象 ID、来源和条件参数写入 schema 描述。
- [Anthropic 工具设计实践](https://www.anthropic.com/research/writing-tools-for-agents)强调明确工具边界、提供有用结果、减少无关上下文，并以真实任务评测描述变更。这里采用“公共说明写共享规则、工具描述写用途与独特后果、参数说明写来源与条件”的分层；完整玩法契约仍由对应开发指南维护。

这些资料没有给出适用于所有 MCP 工具的统一描述字数。简洁应以模型能正确选择和调用工具为前提。合并工具、动态发现或改名会影响现有客户端与调用路径，本次没有足够评测证据支持这些改动，保留现有工具划分。

## 核查结论与调整

现有职责划分符合用途：观察负责当前静态画面，详情负责显式查看，牌组/牌堆/地图工具负责原生页面，动作负责一次提交及后续输入边界。没有发现需要通过重构提示词来扩大游戏信息读取范围的理由。

| 范围 | 发现与处理 |
| --- | --- |
| 公共调用规则 | 明确串行调用并逐次决策；详情仅在状态不变时保留已有许可；按需读取抽牌、费用变化和新回合后的最新数值。明确 `transition.complete` 可以表示等待选择，而非整条效果链已结束 |
| 观察 | 将 `full/actions_only` 的差异移到 `preset` 参数，避免在工具描述重复展开；保留手牌正文和悬停解释须专项查看的边界 |
| 手牌、目标与药水 | 补充手牌 ID 与药水槽位的来源，区分 ID 和数组位置；目标参数写明 `requires_target=true` 时即使只有一个候选也必须提供，否则省略；保留商人目标和战斗外药水用途 |
| 选牌与休息处 | 区分 `selection.cards`、`selection.options` 和 `rest_site.options` 的 ID 来源；保留多选切换、单选可能立即提交、升级预览确认和卡牌束按钮 |
| 牌组、牌堆与地图 | 补充全牌组页目前只在战斗中可打开；保留页面持续打开、关闭方式、底层地图、强制地图不可关闭和抽牌堆显示序不等于抽取序。地图选择参数只取当前可选节点 |
| 奖励、宝箱与商店 | 保留放弃未领奖励、满药水槽、禁止获得药水的不同后果、删牌取消及补货新 ID。将 `open_only` 语义放入参数说明，提示购买时核对 `purchase_result` |
| 事件、先古之民与对话 | 保留当前启用选项、可见致死警告和后续选择的边界，删除重复的未来内容否定句；不改变读取限制 |
| 占卜 | 明确动作回执不带棋盘，后续通过完整观察或 `inspect_event` 读取图像；补齐坐标方向、覆盖格及工具范围。切换大小工具实际走动作许可续接，避免笼统的“查看工具清除许可”产生歧义 |
| 建筑师、遗物与结算 | `proceed` 补上建筑师；遗物描述不再用遗漏可见战斗背景的场景枚举限制用途；结算详情补充已揭示解锁物，返回菜单以 `scene=main_menu` 为准 |
| 截图 | 保留保存路径与尺寸、独占文件名、没有 UI 副作用且不能准备动作的说明；截图不等于向模型返回图像 |

字段路径与许可规则对照 `game_output.py`、各 `*_details.py`、`game_tools.py`、`action_output.py`。场景可用性对照 `GameAdapter.AvailableTools.cs`、`CombatObservation.Status`、`RelicInspection.VisibleHolders` 及对应开发指南；本次没有新增或修改游戏/Godot/RitsuLib API 调用。

同步修正了持续维护文档 `docs/development/mcp.md` 的过时内容：安装段仍写 MCP `0.28.0` / Mod `0.33.0`，连接后的重复工具清单缺少结算与选路工具。版本现与源码及 README 一致，清单改为引用同一文档的完整工具表。非法参数恢复说明补上再次执行动作前重新观察的要求。这些差异已能由当前实现核实，属于文档过时。
