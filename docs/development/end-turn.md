# 结束回合与期间事件

版本与依赖基线见[项目 README](../../README.md#当前版本与前提)。

MCP `end_turn()` 接受可选的[通用 preset](mcp.md#输出预设)，默认 default，事件内空值完整保留；文件协议为 `end_turn`，需要最新观察令牌。

结束回合可用性与提交前拒绝共用判断；待处理选择、卡牌浏览／地图覆盖、屏幕过渡、尚未就绪的回合、不可见／禁用的结束按钮及缺失依赖均明确拒绝。检查发生在提交前，明确未提交且未交互时保留已有许可，可直接继续仍合法的操作；过期观察、提交后失败或未知结果不适用此保证。无需为了取得许可重复基础观察，详见[调用语义](mcp.md#调用和错误语义)。

## 执行与停止边界

工具提交原生 `EndPlayerTurnAction`，从提交前开始记录，到以下边界之一返回。由游戏结算，到达需要玩家输入或下一可行动边界时返回。

| `transition.stop_reason` | 含义 |
| --- | --- |
| `player_ready` | 已恢复玩家可行动且队列为空，已识别的牌堆飞行、生物退场和有限 UI 过渡结束且观察稳定；`end_turn` 还要求后续玩家回合开始通知已发出，出牌、药水和选牌可在同一回合继续 |
| `choice_required` | 原生动作等待本地玩家选择，且已识别其界面；尚未接通操作的类型也会停止，范围见选牌接口 |
| `combat_won` | 原生事件确认本场战斗胜利；不是整局通关 |
| `combat_lost` | 原生事件确认本场战斗失败；不以暂时零血代替结果 |
| `run_won` | 已显示且就绪的原生胜利结算，见[终章结算](run-ending.md)；不表示击败建筑师，非结束回合结果 |
| `run_lost` | 战斗外流程确认整局失败；已显示结算时使用原生结算胜负，见[事件接口](events.md)及[终章结算](run-ending.md)；非结束回合结果 |
| `action_completed` | 战斗外动作已到达可继续的交互边界，例如事件下一页、奖励或地图；非结束回合结果 |
| `selection_resolved` | 非战斗选择已完成，且没有归入已支持的房间边界；须重新读取当前状态 |
| `manual_input_required` | 原生专属界面或弹窗尚未支持，停止自动操作 |
| `action_canceled` | 原生动作已取消并恢复可行动，仍须重新观察 |
| `timeout` | 提交后 25 秒内未到达上述边界，游戏仍可能继续结算 |
| `interrupted` | 原对局、房间或战斗上下文失效，无法继续本次动作；受支持的正常战斗交接见下文 |

选择可能发生在回合结束、敌方行动或回合开始。暴政出现时只返回此前事件，不包含未来选牌结果。使用 [选牌工具](card-selection.md) 处理当前选择，不能再次调用 `end_turn` 代替选择。尚未识别的选择界面仍可能最终返回 `timeout`，不能据此重发动作。

## 返回结构

文件协议保留完整基础观察并增加 `transition`；MCP 返回[精简动作回执](mcp.md#动作返回格式)，事件序列不删项。default 仅省略 card_played.autoplay:false，full 保留该 false；自动出牌的 true 与事件 null 保留。下一回合的手牌、资源和敌人意图按需观察。以下仅为 `transition` 字段的示意：

```json
{
  "transition": {
    "stop_reason": "choice_required",
    "complete": true,
    "events": [
      {
        "sequence": 1,
        "type": "damage",
        "source": {"kind": "card", "name": "Wither"},
        "target": {"id": 0, "kind": "player", "name": "The Ironclad"},
        "hp_loss": 3,
        "blocked": 0
      }
    ]
  }
}
```

`complete` 表示已到达正常停止边界且事件缓冲未截断；支持的记录类别见下方事件表。`timeout`、`interrupted` 或超过 512 条记录时为 `false`。非 `player_ready` 或不完整的结果不向模型宣告可以再次结束回合。底层成功响应只表示本次调用已返回，仍须检查停止原因；传输先超时或游戏异常时适用原有未知结果错误语义。

胜负及不完整回执仍保留当前快照中合法、无需许可的查看工具，游戏动作许可继续独立撤销；支持的可见选择还可列出对应选牌操作。调用成功的详情或页面工具可以刷新后续许可，不能仅因终态列有查看工具便认为结束回合或其他游戏动作已获授权。

## 动作完成与画面稳定

出牌、药水、战斗内选牌继续结算及结束回合共用动作等待。停止原因在等待期间持续重新判断；`player_ready`、`action_completed`、`action_canceled` 以及胜利边界，须等待全局 UI 的四种卡牌预览容器及战斗 UI 的普通、散列预览容器清空，再等待原生 `NCardFlyVfx`、`NCardFlyShuffleVfx`、`NCardFlyPowerVfx` 离开场景，同时等待顶栏金币计数和药水入栏动画结束，再确认观察连续 250 毫秒不变。预览即使暂时被覆盖或尚未显示，也可能随后启动飞牌并改变可见计数，不能仅按当前可见性判断等待结束。原因、状态或可行动条件变化都会重新计时。帧持续推进时按 25 秒截止时间检查，未满足时返回 `timeout/complete=false`，不沿用先前已出现过的正常原因。

这些正常边界以及胜利还检查当前生物尚未完成的死亡任务、生命条显示/隐藏、意图、缩放、生命数字、格挡和能力图标的有限过渡，以及可见手牌描边的显示、隐藏与闪烁补间。死亡节点可以在伤害结算后继续显示数秒，生命条也可能延迟后才渐显；描边渐隐期间仍输出同一个颜色，直至宽度归零才变成 `none`。仅靠 JSON 短暂不变不足以保证返回后的状态令牌稳定。已完成的死亡任务即使仍保留引用，也不会阻止后续复活或行动。实现与验证见[生物退场与观察稳定修复](../research/2026-11-01-action-settling.md)及[手牌描边等待修复](../research/2026-11-01-hand-outline-settling.md)。

原生动作可以先于界面更新完成。例如打击已进入逻辑弃牌堆，显示计数还在等待飞牌落地；工具等待这些有限显示流程结束，再读取可见计数并返回。具体复现与证据见[动作观察边界修复](../research/2026-10-30-action-settling.md)。

战斗外页面也须满足各自的可行动条件；[先古之民](ancients.md#状态与验证)包含仍会改变称号可见性的入场横幅补间，不能仅凭选项已启用就结束旅行等待。

资源等待也包括遗物原生入栏补间，以及佩尔之翼和 Happy Flower 独立激活任务的计数恢复。佩尔之翼第二次献祭后，计数延迟从 `2` 恢复为 `0`；Happy Flower 回合开始回能后，计数暂显 `3` 再恢复为 `0`。这些原生任务结束后再报告普通完成，状态指纹继续包含实际显示的计数。`choice_required` 仍先返回后续选择。实现入口为 [RunUi.ResourceMotionPending](../../src/Sts2Agent/Observation/RunUi.cs)，复现见[奖励替代按钮验证](../research/2026-11-01-reward-alternatives.md)及[Happy Flower 核验](../research/2026-11-09-second-playthrough-feedback.md)。

`choice_required/complete=true` 表示已经到达需要输入的选择边界，父卡牌、药水或回合流程可以仍未完成；此时不会等待它的完整任务，也不因尚未结束的卡牌预览或牌堆飞行动画而卡住选择。预览等待同时覆盖普通出牌生成副本、敌人添加状态牌和战后返还卡牌，例如 Anger 与佩尔之牙；实现及同类字段审查见[动作令牌稳定性审查](../research/2026-11-01-action-stability-audit.md)。选择仍优先停止，不等待被它暂停的流程。死亡与战斗替换按各自边界处理。环境循环动画、伤害飘字等装饰效果可以继续播放。等待依赖游戏继续产生帧；若游戏暂停渲染或主线程停止响应，不能保证恰在第 25 秒返回，由外层 IPC 超时处理未知结果。

奖励选牌与三选一在宣告选择边界前还检查候选是否可选及原生入场动画；例如“发现”和技能药水的三选一存在 350 毫秒原生禁点时间。不能在禁点时间结束前返回可续接的令牌，再让自然出现的 `select_card` 能力使它失效。这只等待选择界面准备好，不等待玩家作答。 网格选择还等待当前可见卡牌的有限描边 Tween；例如锻造取消预览会有 0.5 秒淡出，须等其完成后才能返回稳定令牌。返回火堆后还等待说明文字的 1 秒淡出，见[复现与修复](../research/2026-11-01-compact-actions.md#网格选择描边等待)。

后续 `get_observation` 和截图读取调用时的当前画面，不自动等待；玩家手动输入、页面变化或未覆盖的第三方异步流程仍可能使观察变化。本版验证针对已核对的原生卡牌、牌堆、资源显示及生物有限过渡，不能据此推断全部机制均已覆盖。

`get_state` / `get_observation` 只返回当前观察，不回放战报；战报中的 `events` 不参与基础观察的 `snapshot_id`。相同请求 ID 的已有响应缓存保留原战报。进程重启、缓存删除或客户端未收到响应后的事件恢复尚未实现。MCP 可以复用成功且可继续行动的动作结果，新令牌的取得与失效规则见[调用语义](mcp.md#调用和错误语义)。

## 事件语义

`sequence` 从 1 递增，表示本记录器捕获顺序，不承诺任意嵌套效果的完整因果树。

| `type` | 内容 |
| --- | --- |
| `combat_started` | 同次动作已有战斗后进入新战斗的上下文分隔，仅含 `sequence/type`；后续事件中的角色和卡牌 ID 属于新战斗，不附送遭遇或敌人信息 |
| `card_played` | 已进入出牌流程的牌、`autoplay` 及可选目标；full 保留 autoplay:false，default 省略该 false，true 表示自动出牌。手动出牌省略 source，自动出牌的 source 为已核实触发来源或 null；不代表全部效果已完成 |
| `card_selected`、`card_deselected` | 选牌 UI 实际接受的选中／取消，仅含 `sequence/type/card`，`card` 为原候选的 `id/name`；名称取输入前同次公开快照，不可读时为 `null`，未知／锁定牌只保留实际公开的占位文字。自动替换先取消旧牌再选中新牌，最后一张自动提交仍记录选中；确认、进入预览或关闭页面不算取消，随机结果不随选中附送。default/full 都保留，包括 `name:null` |
| `card_drawn`、`card_discarded`、`card_exhausted` | 本地玩家牌的公开移动；抽牌在原生历史写入时记录，手牌弃置和消耗在原生入堆事件时记录，先于其后续触发效果 |
| `card_added` | 已公开展示的新生成牌或永久入组牌，含 `card.id/name` 和 `pile`：`deck` 为永久牌组，`hand/draw/discard/exhaust/play` 为战斗中的手牌、抽牌堆、弃牌堆、消耗堆和出牌结算区；UI 未明确显示去向时为 `null`，不输出堆内位置或顺序 |
| `card_moved` | 已有牌的可见跨战斗牌堆移动，固定含 card.id/name、from_pile、to_pile；牌堆为 hand/draw/discard/exhaust/play，不包含 position、堆内位置或顺序。已由抽牌、弃置、消耗或手牌进入出牌流程表达的同次移动不重复报告 |
| `card_removed`、`card_upgraded`、`card_downgraded`、`card_enchantment_changed` | 本地玩家永久牌组中的删除、升级、降级或附魔变化；附魔包括附加／清除及已附着实例的数量／基础变量直接修改，以实际被修改的永久卡牌实例为准。含 `card.id/name` 和 `pile:"deck"`，名称来自期间公开身份，不保证已更新为变更后的标题；不附送牌面正文或内部数值 |
| `card_stats_changed`、`card_energy_cost_changed` | 本地永久牌组中基础变量或基础能量费用直接变化，仅含 `card.id/name` 和 `pile:"deck"`；不输出变量名、旧值、新值或未展开正文 |
| `relic_obtained`、`relic_removed` | 本地玩家取得或失去已公开的遗物，仅含 `relic.name`；不虚构遗物序号或悬停正文 |
| `relic_melted` | 已公开的蜡制遗物实际呈现熔化图标，仅含 `relic.name`；遗物仍留在栏位，不生成移除事件，普通禁用不算熔化 |
| `relic_counter_changed` | 本地玩家已显示遗物的计数标签变化，含 `relic:{name}`、`before`、`after`；两端为实际显示的整数或null，至少一端为整数且值不同。null表示图标可见时没有显示计数，default也保留两端 |
| `orb_channeled`、`orb_evoked`、`orb_removed` | 本地玩家充能球实际入栏、开始激发或离栏，含玩家 `target`、`orb.name` 和从 0 起的 `slot_index`；不附送被动／激发数值或悬停正文 |
| `orb_slots_changed` | 本地玩家公开充能球槽位总数变化，含玩家 `target` 与 `before/after`，均为 0..10 的整数 |
| `potion_obtained` | 实际入栏并公开展示的药水，含 `potion.slot_index/name`；取得失败不生成事件 |
| `potion_used`、`potion_discarded` | 已见药水的 `potion.slot_index/name`；使用事件在原生移除时记录，后续效果可能仍需选择 |
| `damage` | 实际 `hp_loss`、`blocked`，可选伤害角色与来源；普通直接伤害包含全部格挡和致命一击，生命数字未公开时 `hp_loss` 为 `null` |
| `hp_changed` | 未作为伤害记录的公开 HP 变化，含 `before`、`after`，例如治疗或直接处决；生命数字隐藏时不返回内部绝对值 |
| `energy_changed`、`stars_changed` | 可读战斗计数的本地玩家能量／星星变化，含玩家 `target` 及公开端点；`after` 为非负整数，`before` 亦为非负整数，首次星星显现但旧值未公开时为 `null`；等待真实数字达到本次目标，滚动动画不逐帧生成事件 |
| `max_energy_changed` | 当前战斗能量标签分母的可见变化，含玩家 `target` 和非负整数 `before/after`；仅记录实际采样到的公开变化，不读取隐藏容量或补出未显示中间值 |
| `max_hp_changed` | 本地玩家顶栏或可见友方召唤物生命条的最大生命变化，含玩家或友方 `target` 及非负整数 `before/after`；友方等待实际显示端点，隐藏取消且恢复不补发 |
| `gold_changed` | 顶栏可读的本地玩家金币变化，含玩家 `target` 及非负整数 `before/after`；按原生通知记录，金币计数动画不拆成多个事件 |
| `block_changed` | 格挡变化，含 `before`、`after`；普通伤害消耗的格挡由 `damage.blocked` 表达 |
| `power_changed` | 名称、`change`（`applied` / `modified` / `removed`）及显示计数前后值；无数字图标或不存在的一侧用 `null` |
| `died`、`revived`、`creature_added` | 可见实例的死亡、复活或加入，分别保留；未复活前的重复死亡通知只记录一次，复活后可再次记录死亡 |

遗物计数按原生标签刷新记录，同一帧的多次刷新也保留。Pen Nib 在第十张攻击开始结算时先将计数归零，再进入约一秒的激活显示，因此可记录 `9→0→10→0`；该攻击由原生效果翻倍，`10` 表示激活中的标签。若批次继续出牌，动画结束后恢复为当时的累计计数。具体对照见[Pen Nib 核验](../research/2026-11-09-necrobinder-feedback.md#4-pen-nib-计数)。

### 战斗与对象身份

`combat_started` 仅在同次动作再次进入战斗时使用；从战斗外进入首场战斗，以及同场复活、阶段变化或新回合均不生成。新战场至少经过一次绘制且可读后发布；当前动作结束前仍未公开或再次切换时丢弃，后续请求不补发。角色 `CombatId` 和战斗卡牌 ID 可以在新战斗重新分配，不能把标记前的 ID 用于标记后的出牌或选目标；永久牌组变化仍以 `pile:"deck"` 区分。

充能球的 `slot_index` 沿原生队列从右到左编号，0 为最右槽；与观察中球对象的编号一致，数组位置与编号的映射见[充能球顺序](combatant-inspection.md#充能球顺序)。记录时机为：生成使用首次实际可见的位置，激发使用触发时的位置，离栏使用离开前的位置；球离栏后后续位置会变化，它不是稳定球 ID。双重释放的两次激发分别记录，实际离栏另有一条 `orb_removed`；缩槽丢弃尾部球只记录离栏与槽位数变化，不推断为激发。新球先保留事件位置，至少经过一帧且实际可见后发布；未展示就离栏、被隐藏、离屏或被页面覆盖的身份不发布，恢复后不补记。槽位数至少经过一帧并确认实际可见，同次未公开的中间端点合并；隐藏变化不回放。已有球被动数值变化仍按需观察，当前没有专门的被动触发／数值变化或替换球事件。

角色沿用战斗 `CombatId`，同一实例复活不换标识。牌沿用基础观察的稳定 ID；已经见过或期间实际展示的完整名称可以保留，遵循[可见牌名规则](observation.md#手牌与身份)，未识别牌名为 `null`。开始记录时也记住当前可见确认区中的已选牌，避免确认后的消耗事件丢失名称。来源仅提供已核实的卡牌、power、遗物或药水名称，不附送完整效果；未知来源为 `null` 或缺省。不输出敌人内部 move ID、未来动作、未发生的随机结果或未展示牌堆内容。

`damage.source` 表示本次直接伤害的来源，`died.source` 只保留对该实例的致命伤害或明确 Doom 处决来源，均不表示整条动作因果链。首领死亡后随从被清理，以及召唤物攻击后自行死亡，不把其剩余 HP 算成外层牌或攻击的伤害；可见清零可产生 `hp_changed`，死亡来源为 `null`。真正群攻命中与关联清理分别记录；未知来源不根据当前牌名、意图或 Minion 图标推断。怪物攻击通过 `damage.actor` 标识实际攻击者，不虚构卡牌来源。复现与活雾验证见[死亡来源核查](../research/2026-11-01-death-attribution.md)。

### 卡牌加入与移动

战斗新生成牌在原生生成历史处保留位置，实际入堆确定初次目标；牌名取期间真正显示的牌，去向须有可见手牌、结算区或原生入堆动画证据。预览只公开身份时 `pile:null`，同次动作稍后的实际飞牌可以补全该字段；页面隐藏或覆盖后不补发未见去向。Reave 生成 Soul 后紧接 Fetch 抽走时，原生预览可能按当前手牌重新决定飞牌目标，初次去向仍为 null；后续 `card_drawn` 和当前手牌分别表达已确认的移动与位置。手牌满时以重定向后的目标为准，后续普通移动不会新增 `card_added`，也不能改写已确认的初次目标；抽牌堆顺序始终不公开。实现和验证见[加入去向核查](../research/2026-11-02-card-add-destinations.md)及[连招对照](../research/2026-11-09-necrobinder-feedback.md)。

已有牌移动由独立记录器配对移出／进入通知，等真实手牌、结算区或飞牌动画公开后发布 card_moved。匿名牌背不能自动提供身份：只有明确选择、可识别的出发牌面或本次调用开始时已唯一的来源才可关联；期间变成最后一张不能单凭内部移出顺序推断。原生洗牌的异步上下文抑制逐牌移动记录，避免序号泄露洗牌顺序。隐藏／覆盖、没有可见移动、同堆重排不补记，恢复显示也不回放隐藏区间。

draw→hand 不一定是抽牌，例如无休手斧可以从抽牌堆直接回手。仅在原生 Draw 流程实际写入同次 CardDrawn 历史时去重；不会仅因来源是抽牌堆就删除移动。原生 Draw 仍在执行时先等待结果核对，不把期间挂钩中的其他回手直接推断为抽牌。

头槌手动选择的移动位于真正恢复父流程的选牌回执；只有一张弃牌、原生自动选择时位于 play_card 回执。明耀打击回抽牌堆、无休手斧下回合回手，以及刀刃陷阱从消耗堆自动出牌均走同一记录器；原生跳过牌堆视觉的后续自动出牌不虚构移动动画。牌名仅复用同一战斗中已经公开的身份，未识别为 null；即使选择提示或正文提到堆顶，也不在移动事件中添加位置。实施、实际样例与限制见[结束回合及移动修复](../research/2026-11-04-turn-transitions-implementation.md)。

### 记录顺序与身份关联

所有游戏动作共用本次请求的有界缓冲；玩家资源、物品、永久牌组、战斗及药水事件使用同一个递增 `sequence` 和 512 个记录位置上限，超出时 `complete:false`。进入战斗后继续使用该缓冲，保留此前记录；结束或异常时释放，不带入下一次调用。战斗内 HP 由战斗记录器负责，避免同一次伤害又生成一条重复 `hp_changed`。

遗物计数由独立RelicCounterJournal在原生NRelicInventoryHolder.RefreshAmount完成后及观察采样时读取真实标签，复用RelicInspection的完整已显示列表；离屏、不可悬停不影响静态计数。每个实际显示的连续变化分别记录，重复刷新不重复，不读取DisplayAmount补数。隐藏、透明、实际裁剪、页面不可读或持有者更换时丢弃旧基线；新取得／重新显示只建立基线，不补记期间变化。图标可见时标签出现／消失可以产生null对照；遗物取得、移除及熔化仍使用各自事件。记录器随动作结束释放。

原生通知可能先于展示动画；记录器先保留位置，身份公开后才发布，最终序号连续。未公开或期间被遮挡而丢弃的位置不进入回执，也不在后续调用补记。位置上限同时约束已发布与待展示的记录。永久变牌以旧牌 `card_removed` 和新牌 `card_added` 表达，不推断一一配对，不把随机循环预览当作结果。预览克隆和战斗临时升级不生成永久变化事件。药水使用／丢弃在所有动作统一订阅，包括事件濒死救回等附带移除，内部战斗记录器不重复订阅。

直接牌面变化采集经过已核对的 `DynamicVar.BaseValue`、`CardEnergyCost.SetCustomBaseCost` 和 `EnchantmentModel.Amount` 入口，只接受实际属于本地永久牌组的实例；预览值、战斗副本修改、临时费用及全局 power 修正不算永久修改。升级／降级、附魔附加／清除及其内部重算使用原有高层事件，避免重复。单动作内，同张永久牌同类直接修改合并一次，位置对应首次采集；不能据此还原每个内部数值或变化次数。三种身份型变化事件的协议字段严格限于 `sequence/type/card/pile`。

可见战斗副本通过真实 `DeckVersion` 且模型身份相同，才可建立永久原牌的基础名称；不按同名匹配，也不继承战斗临时升级的“+”。永久原牌直接展示时可保留其完整可见名称。原牌与战斗副本是不同实例，ID 可以不同；`pile:"deck"` 中的 ID 不能当作手牌 ID 出牌，牌组页仍使用独立的浏览 ID。未知身份先保留位置，真实展示后才发布；整页隐藏则取消。新数值按需通过卡牌详情或牌组页读取，事件不自动展开正文。

### 资源与顶栏

能量与星星由原生通知触发，但端点取期间实际公开的计数。同一次数字刷新前的多次通知会合并，保留首次通知的位置，不输出未展示的中间绝对值，也不把滚动动画的逐帧数字当作独立效果。数字标签或战斗页面隐藏时取消尚未发布的记录；恢复后只建立新公开基线，不补发隐藏变化。缺少公开旧值时不从模型推算；星星计数器首次显现可返回 `before:null`，不补成内部旧值 `0`。首次布局例外只允许尚无面积的可见数字标签，已经布局的标签离屏、被裁剪或隐藏时取消等待。

最大能量没有独立原生变化通知，按实际标签分母采样，记录位置表示首次观察到变化的时刻。蜡制遗物熔化优先在状态通知后检查实际图标，并补采无通知的显示刷新；两者都不承诺比采样粒度更细的中间顺序。标签或图标隐藏时清除基线，恢复后不补发。容量不变时不占用事件位置。

战斗外损血和治疗使用 `hp_changed`，不根据事件选项文字推断伤害来源。最大生命增加可能先改变上限、再治疗，随后又受到损血，分别记录真实变化，不折叠成净差值。资源记录检查实际顶栏与对应数字标签；隐藏时不记录，恢复可见后以公开数值重新建立基线，不补记隐藏区间的变化。战斗外玩家尚无 `CombatId` 时使用 `id:0, kind:"player"`，名称仍由当前角色身份提供。

原生卡牌网格、发现牌、卡牌奖励及卡牌包页在进入／退出过渡中，页面尚未能接受输入不等于顶栏已隐藏；仍真实画出的顶栏继续采样资源及物品事件。地图、牌组、模态覆盖与真正隐藏的控件仍按各自可见条件判断，隐藏期间的变化不在恢复后回放。

## 实现与限制

已知房间切换期间的金币／生命通知保留切换前公开基线，目标画面实际显示对应端点后再发布，例如 Maw Bank、Planisphere 的入房间效果。一次遮挡区间没有显示的中间数值合并为公开端点；分别显示的变化逐次保留，事件位置对应首次通知。真正隐藏的顶栏／标签、覆盖详情或未知弹窗取消待显示记录，恢复后只建立新基线；战斗日志已负责的生命变化不重复记录。问题依据见[实测反馈复核](../research/2026-11-08-early-playtest-feedback-review.md)。

RitsuLib 提供统一通知，用于出牌、生成牌、角色加入及生命周期核对。抽牌事实使用原生历史写入点，弃置与消耗使用原生牌堆事件，避免 RitsuLib 后置通知在嵌套触发后才到达而倒序或漏记。原生角色事件补齐 HP、格挡、powers、死亡与复活；原生战斗事件决定胜负，原生选择界面识别交互边界。伤害通过已核对的 `CreatureCmd.Damage` 和 `Creature.LoseHpInternal` 入口补录，保留事件发生位置并避免丢失最后一击。原生 `DamageResult` 的格挡字段在同一流程稍后赋值，返回前补齐。

来源通过异步执行上下文传递；惊逃自动出牌与灾厄处决另外保留明确来源。订阅在返回或异常时释放。所有游戏动作由统一作用域管理当前战斗记录器，战斗内动作借用同一实例；原生重置前刷新并释放旧记录器，避免将清理当成效果，新战斗启动时先同步卡牌 ID，再接入同一缓冲。原生房间进入任务及战斗启动期间不提前报告旧胜利、`selection_resolved` 或普通完成，真实选择仍可暂停；外部对局替换的 `interrupted` 与人工输入边界保留。等待和停止条件随新战斗更新；外层返回前也刷新已经释放的旧日志中延后填写的伤害格挡字段。游戏访问留在主线程，文件与模型等待在外部。

偷窃草蜢的首回合会记录 Swipe 的 `power_changed/applied`、攻击伤害及 Escape Artist 计数变化。当前没有专门的偷牌事件，回执不附送被偷牌名或移出位置；已公开的被偷卡牌预览及归还说明可通过 `inspect_combatants` 的 Swipe 提示读取。实测完整回执与可见性核对见[状态说明验证](../research/2026-11-01-power-descriptions.md)。

奥斯提攻击的 `actor` 为友方奥斯提，`source` 为所用卡牌；君王之剑攻击的 `actor` 为玩家，`source` 为君王之剑卡牌，不创建独立的剑生物。奥斯提代受伤按原生结果分别记录主人格挡、奥斯提生命损失及超出其生命后回到主人的伤害；原生未调用主人 `LoseHpInternal` 的格挡结果从本次新产生的伤害记录补录，按同一结果实例去重。首次加入仅在至少一帧绘制后公开身份，覆盖时取消且不补发。来源与验证见[核查及实现记录](../research/2026-11-02-companions.md)。

记录范围以上方事件表及可见性规则为准。未接入的直接存储字段修改、特殊机制、其他复杂召唤和第三方 Mod 效果仍可能缺项；未知选择、断线恢复与超时后持续事件尚未覆盖。充能球被动触发、数值变化和替换球目前没有专用事件。升级游戏或 RitsuLib 后重新验证受影响入口。

游戏动作的资源、永久牌组与战斗记录通过[Events](../../src/Sts2Agent/Events/)统一作用域组合，结束回合的提交与等待入口见[GameAdapter.EndTurn](../../src/Sts2Agent/Adapter/GameAdapter.EndTurn.cs)。设计与历史覆盖证据见[初始调研](../research/2026-10-29-end-turn-events.md)、[覆盖审查](../research/2026-11-01-transition-event-coverage.md)、[永久牌组事件](../research/2026-11-01-permanent-card-events.md)、[充能球事件](../research/2026-11-01-orb-events.md)及[战斗交接](../research/2026-11-01-combat-handoff.md)。

## 验证

先按 [运行指南](roundtrip.md) 准备隔离实例。一个终端用 `python3 scripts/run_roundtrip.py --turn-scenario tyranny` 启动新实例；另一个终端运行：

```sh
python3 -m tests.game.verifiers.verify_end_turn --ipc-dir .tmp/roundtrip/ipc --scenario tyranny --report .tmp/turn-tyranny.json
```

验证只用于带相同场景参数的新测试实例主菜单。场景入口改变测试初始条件，仅由 `STS2_AGENT_TEST_MODE=1` 下的 `start_test_combat` 使用，不是公开玩法工具。每个场景须重启实例，不能在正式对局执行；`--windowed` 可验证图形显示。

其他场景名称：`normal`、`wither`、`wither_death`、`enemy_death`、`retain_choice`、`boulder`、`doom`、`stampede`、`revive`、`blocked`、`hellraiser`、`exhaust_block`、`hidden_hp`。其中 `revive` 连续验证多个回合，以同时取得千足虫死亡及后续复活证据；`hellraiser` 和 `exhaust_block` 检查触发顺序，`hidden_hp` 检查未公开生命数字不进入日志。

[选牌](card-selection.md)、[出牌](card-play.md)、[搜刮](rewards.md)及其他游戏动作复用本页停止原因和事件格式；各自允许的输入及后续流程见对应接口。资源、永久牌组、充能球与战斗交接的专项验证见上文记录，历史数量不表示当前代码已重新验证。
