# sts2_agent

通过《杀戮尖塔 2》（Slay the Spire 2）的 Mod 接入游戏，向大语言模型（LLM）提供读取状态和执行动作的工具，逐步实现自主游玩。

## 当前状态

项目处于初始化阶段，目前只有协作约定与文档，尚无可运行的 Mod、工具服务或 LLM 客户端，也没有构建、安装和启动命令。

已完成本地游戏文件与社区库的初步核对，详见 [Mod 接入基线调研](docs/research/2026-10-28-modding-baseline.md)。这份记录是调查起点，不代表已经验证 Mod 加载或自动游玩。

## 接入方向

候选方案由三部分组成，具体实现与依赖尚待验证：

| 部分 | 职责 |
| --- | --- |
| 游戏内 Mod | 读取当前状态，在游戏允许的时机执行合法动作，并返回结果 |
| 工具接口 | 对外提供结构化状态、可用动作、参数约束和错误反馈，隔离游戏内部对象 |
| LLM 客户端 | 根据观察选择动作、调用工具，持续记录决策与执行结果 |

优先验证 C# Mod 方案。本地安装提供了游戏程序集、Godot C# 绑定和 Mod 加载相关文档；具体 API 及线程约束仍须逐项核实。工具协议、通信方式、外部程序语言和模型提供方暂未确定，MCP 可作为候选，但不是既定要求。

[BaseLib](https://github.com/Alchyr/BaseLib-StS2) 是社区 Mod 基础库，[RitsuLib](https://github.com/BAKAOLC/STS2-RitsuLib) 提供生命周期、补丁和其他共享功能。它们是待评估的依赖，不等于现成的 LLM 控制接口，也不预设必须同时引入。应先核对原生能力和目标版本，再按实际需要选择依赖。

## 首个验证目标

先在单人游戏的一处可交互场景完成一次完整往返：

1. 游戏成功加载最小 Mod，并能确认初始化结果。
2. 外部程序读取可用于决策的结构化状态和可用动作。
3. 外部程序提交一个动作，Mod 核对当前状态与参数，通过游戏正常流程执行。
4. 返回执行结果和更新后的状态；无效或过期请求得到明确错误。

该流程先用确定性的测试客户端验证，再接入 LLM。之后逐步扩展战斗、选牌、奖励、地图、事件和商店等场景，最终覆盖完整一局。完整游玩是长期目标，当前尚未实现上述能力。

## 本地游戏与开发前提

本机 Linux Steam 安装位置为：

```text
~/.local/share/Steam/steamapps/common/Slay the Spire 2
```

此路径仅作为本机参考，后续实现应允许配置。开发与运行需要自行安装游戏；仓库不包含游戏程序集、资源或存档。游戏及依赖更新后，应重新核对兼容性，不能直接以社区库的最新版本适配本地旧版本。

正式开发前还需确认 C#/.NET 与 Godot 工具链、Mod 打包及加载方式、依赖兼容版本，以及状态与动作接口。后续有可运行实现时，再补充经过实际验证的安装与使用说明。
